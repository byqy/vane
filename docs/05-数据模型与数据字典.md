## 1. 建模约定

通用规则（命名、主键、审计列、逻辑删除、时间、枚举、外键）见 [01 §7](01-技术栈与规范基线.md)。本文只记录项目特有约定：

| 项 | 约定 |
|---|---|
| 模块前缀 | `iam_`（身份与权限）、`sys_`（系统与平台）、`cms_`（内容） |
| 表名 | 单数、小写下划线：`sys_user`、`iam_role` |
| 主键 | `id uuid primary key default uuidv7()` |
| 审计列 | 业务实体表含 `created_at / created_by / updated_at / updated_by` |
| 逻辑删除 | 仅**业务实体**使用 `deleted_at`；关联表与日志表不使用 |
| 版本列 | 可并发编辑的实体含 `version bigint not null default 0` |
| 唯一约束 | 与逻辑删除共存时，一律用部分唯一索引 `where deleted_at is null` |
| 关联表 | 物理删除，主键为复合唯一（如 `(user_id, role_id)`） |
| 日志表 | 只增不改不删：不提供更新与删除接口，应用账号不授予 UPDATE / DELETE |
| 多语言 | 运营内容按 `(主表 id, locale)` 同行存储；界面文案走仓库文件，不入库 |
| JSON 列 | 仅存非检索用途的结构（参数快照、配置值）；需要过滤的字段必须独立成列 |

### 4.4 权限点（代码定义，不入库）

权限点与菜单定义在代码目录 `PermissionCatalog`（ADR-021），数据库不保存权限点行，
只保存「角色 → 权限码」的授权关系。这样新增权限点只改代码与文案，不产生数据库变更。

| 项 | 约定 |
|---|---|
| 定义源 | `vane-iam` 的 `PermissionCatalog` 枚举：`code`、`type`（MENU / BUTTON）、`parentCode`、`path`、`component`、`icon`、`sortNo`、`visible` |
| 编码格式 | `模块:资源[:动作]`，如 `system:user:create`；根菜单只有两段（如 `system`） |
| 文案键 | 由 code 派生：MENU → `menu.<路径>`，BUTTON → `perm.<路径>`，连字符转驼峰（如 `perm.system.user.resetPassword`），译文在 `packages/shared/src/locales/perm/` 与基础文案 |
| 菜单 | MENU 节点决定前端菜单与路由，`/auth/me` 按用户已授权 code 过滤后下发 |
| 授权树 | `/admin/permissions/tree` 由代码目录生成，节点 `id` 与 `code` 相同 |

## 11. 不落库的临时状态

以下数据生命周期短、并发敏感，统一放 Valkey，不入库：

| 数据 | 存储 | TTL |
|---|---|---|
| access 令牌哈希与状态 | Valkey | 15 分钟 |
| `mfaToken` 哈希 | Valkey | 5 分钟 |
| 注册 / 找回密码 / 邮箱验证码 | Valkey | 10 分钟 |
| 登录失败计数 | Valkey | 15 分钟（按账号 + IP） |
| 接口限流计数 | Valkey | 按限流窗口 |
| 业务缓存 | Valkey | 按业务 |

登录锁定状态持久化为 `iam_user.locked_until`，用于跨重启与后台展示；计数本身由 Valkey 承担。
