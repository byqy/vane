## 1. 项目与架构

| 术语 | 定义 |
|---|---|
| vane | 项目代号（风向标），用于包名、工件名、镜像名与 npm scope |
| 模板 / 脚手架 | 可整体复制到新项目的工程骨架与文档体系 |
| 单租户 | 一套部署服务一个机构；机构内用组织树做数据可见性，不存在租户隔离 |
| 组织 / 部门 | `iam_dept` 中的树节点，是数据范围的锚点 |
| 模块 | Maven 子工程或 pnpm 包，如 `vane-iam`、`packages/shared` |
| 分层 | 模块内部的 `api → application → domain → infrastructure` 四层 |
| ADR | Architecture Decision Record，架构决策记录，位于 `10-ADR/` |

## 2. API 与错误

| 术语 | 定义 |
|---|---|
| 资源式表示 | 成功响应直接返回资源或集合本身，不使用 `{code,msg,data}` 外层包装 |
| Problem Details | RFC 9457 定义的错误响应体：`type`、`title`、`status`、`detail`、`instance` |
| `type` URI | Problem Details 中稳定、语言无关的问题类型标识，本项目用相对路径 `/problems/<编码>` |
| 业务码（`code`） | Problem Details 扩展成员，机器可读的细分标识，如 `IAM.USER.EMAIL_TAKEN` |
| 错误码注册表 | 业务码到 HTTP 状态、`type`、i18n key、可重试性的唯一映射表 |
| 状态码契约 | 「什么场景返回哪个状态码」的全站唯一口径表（03 §3） |
| 资源式集合 | 列表响应形如 `{ items, page }`，是集合自身的表示 |
| 游标分页 | 使用 `page[size]` + `page[after]`，适合大数据量与信息流 |
| 页号分页 | 使用 `page[number]` + `page[size]`，适合后台表格与跳页 |
| 条件请求 | 通过 `ETag` / `If-Match` / `If-None-Match` 实现的并发控制与协商缓存 |
| 幂等键 | `Idempotency-Key`，客户端生成，服务端保存 24 小时，重复提交返回首次结果 |
| 信封 | 对响应外层的统称；本项目不使用统一信封，仅在错误时使用 Problem Details |

## 3. 认证与权限

| 术语 | 定义 |
|---|---|
| access 令牌 | 短期访问令牌（15 分钟），只存客户端内存，随请求头发送 |
| refresh 令牌 | 长期刷新令牌（7 天），存 `__Host-REFRESH` HttpOnly Cookie |
| 令牌族（family） | 一次登录产生的 refresh 令牌链，共享 `familyId` |
| 轮换（rotation） | refresh 一次性使用，刷新后旧值失效并下发新值 |
| 复用检测 | 已使用过的 refresh 再次出现即判定泄露，撤销整族 |
| MFA | 多因素认证；本项目一期实现 TOTP |
| TOTP | 基于时间的一次性密码（RFC 6238），不依赖外部服务 |
| 恢复码 | MFA 的一次性备用码，设备丢失时使用 |
| mfaToken | 密码通过后、MFA 校验前的一次性短期凭证（5 分钟） |
| step-up | 二次提权：敏感操作前要求重新验证身份 |
| RBAC | 基于角色的访问控制 |
| 权限点 | 最小授权单元，编码形如 `模块:资源:动作`，定义在代码目录 `PermissionCatalog`（ADR-021） |
| 数据范围 | 用户可见的数据集合范围：全部 / 本组织及以下 / 本组织 / 仅本人 / 自定义 |
| 越权 | 访问了未授权的功能（垂直）或数据（水平） |
| 豁免 | 显式声明不受数据范围约束的全局查询，需白名单与审计 |

## 4. 国际化

| 术语 | 定义 |
|---|---|
| locale | 语言与地区标识，BCP 47，如 `zh-CN`、`en` |
| 回退链 | 找不到译文时的查找顺序：`zh-CN → zh → en` |
| 语义 key | 按含义命名的文案标识，如 `user.form.email.label` |
| ICU MessageFormat | 支持占位符、复数、选择的消息格式语法 |
| 伪语言 | 用于布局测试的构造语言（如 `en-XA`），检验文本膨胀后的溢出 |
| TMS | 翻译管理系统，一期仅预留导入导出接口 |

## 5. 数据与运维

| 术语 | 定义 |
|---|---|
| UUIDv7 | 时间有序的 UUID 版本，由 PG 18 内置 `uuidv7()` 生成 |
| 逻辑删除 | 以 `deleted_at` 标记删除，配合部分唯一索引保留唯一约束 |
| 部分唯一索引 | 带 `where` 条件的唯一索引，如 `where deleted_at is null` |
| 乐观锁 | 以 `version` 列检测并发修改冲突，对外体现为 `ETag` / `If-Match` |
| 审计四列 | `created_at`、`created_by`、`updated_at`、`updated_by` |
| 扩展-收缩迁移 | 先加新结构、再改代码、最后清理旧结构的兼容式数据库变更方式 |
| 设计令牌 | 主题的最小变量集合（`--vane-*`），映射到组件库变量（`--el-*`） |
| 结构化日志 | 以 JSON 字段输出的日志，便于检索与聚合 |
| traceId | 贯穿一次请求的链路标识，日志、响应头、Problem Details 共用 |
| SBOM | 软件物料清单，记录依赖成分，用于供应链合规 |
| RPO / RTO | 恢复点目标 / 恢复时间目标 |

## 6. 流程

| 术语 | 定义 |
|---|---|
| 门禁 | CI 中必须通过的检查项，失败即阻断合并 |
| 契约测试 | 校验接口结构、状态码、错误模型与错误码一致性 |
| 越权矩阵 | 以不同身份对受控表的不同接口逐项验证权限的测试集合 |
| 决策点（D-xx） | 需要负责人拍板的设计选择，结论记录于 ADR |
