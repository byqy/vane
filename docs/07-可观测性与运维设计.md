## 1. 目标与原则

- **可观测三支柱**：日志（发生了什么）、指标（趋势与容量）、追踪（一次请求跨组件链路）。
- 单实例或共享卷部署（D-12），不引入 Prometheus + Grafana 常驻依赖作为**必需项**；提供可选接入方案。
- 默认开箱即可排查：日志到 stdout、健康检查可用、关键指标可读。

## 2. 日志

### 2.1 字段规范

结构化 JSON，与 [01 §5.4](01-技术栈与规范基线.md) 一致：

| 字段 | 说明 |
|---|---|
| `timestamp` | RFC 3339 UTC |
| `level` | `ERROR` / `WARN` / `INFO` / `DEBUG` |
| `logger` | 日志来源类 |
| `traceId` | 链路标识，与响应头、Problem Details 一致 |
| `userId` | 可空 |
| `method` / `path` / `status` / `durationMs` | 请求摘要 |
| `code` | 业务码（错误日志必带） |
| `message` | 已脱敏 |

### 2.2 级别与内容

| 级别 | 使用场景 |
|---|---|
| `ERROR` | 需要人工介入的失败（未捕获异常、依赖不可用） |
| `WARN` | 可自愈但需关注（重试、降级、配额接近上限） |
| `INFO` | 业务关键动作（登录、权限变更、发布、任务执行） |
| `DEBUG` | 开发排查；生产默认关闭 |

**禁止**记录：密码、令牌、完整身份证、完整手机号、完整邮箱、请求体中的敏感字段。

### 2.3 输出与保留

- 容器部署输出 stdout/stderr，由 Docker 日志驱动轮转（`max-size=50m`、`max-file=5`）。
- 裸机部署写入 `logs/app.log`，按天与大小双维度轮转，保留 30 天。
- 持久化审计日志在数据库（见 05），与应用日志分离。

## 3. 指标

通过 Spring Boot Actuator + Micrometer 暴露 `/actuator/prometheus`（默认仅内网可访问）。

| 类别 | 关键指标 |
|---|---|
| HTTP | 请求量、延迟分位（p50/p95/p99）、错误率（4xx/5xx 分开） |
| JVM | 堆使用、GC 次数与停顿、线程数、类加载 |
| 连接池 | HikariCP 活跃/空闲/等待、获取超时次数 |
| 缓存 | 命中率、命令延迟、连接数（Valkey） |
| 业务 | 登录成功/失败数、MFA 校验失败数、导出次数、定时任务执行结果 |

指标命名遵循 Micrometer 约定（`http.server.requests`、`jvm.memory.used` 等），不自定义风格。

## 4. 追踪

- 接受 W3C `traceparent`，缺省由服务端生成；`traceId` 贯穿日志、响应头、Problem Details 与审计记录。
- 采样：默认 100% 记录 `traceId`，不默认上报到外部 APM；接入 OpenTelemetry 时按 10% 采样起步。
- 前端错误上报携带 `traceId`，可反查后端日志。

## 5. 健康检查

| 端点 | 用途 | 暴露 |
|---|---|---|
| `/actuator/health/liveness` | 进程存活 | 容器编排探针 |
| `/actuator/health/readiness` | 数据库/缓存就绪 | 容器编排探针 |
| `/actuator/health` | 汇总 | 内网 |
| `/actuator/info` | 版本与构建信息 | 内网 |

Actuator 其余端点默认关闭；`env`、`heapdump`、`threaddump` 等敏感端点不得对外暴露。

## 6. 告警

| 规则 | 阈值 | 级别 |
|---|---|---|
| 服务不可用 | 健康检查连续 3 次失败 | 紧急 |
| 错误率 | 5xx 占比 > 1%（5 分钟） | 紧急 |
| 延迟 | p95 > 1s（5 分钟） | 警告 |
| 数据库连接池耗尽 | 等待数 > 0 持续 1 分钟 | 紧急 |
| 磁盘 | 使用率 > 85% | 警告 |
| 备份失败 | 任一备份任务失败 | 紧急 |
| 登录失败激增 | 5 分钟内失败 > 100 次 | 警告（疑似爆破） |
| 定时任务连续失败 | 连续 3 次 | 警告 |

通知渠道由客户环境决定（邮件 / 企业微信 / 钉钉 webhook），模板提供 Webhook 适配点。

## 7. 备份与恢复

| 对象 | 方式 | 频率 | 保留 |
|---|---|---|---|
| PostgreSQL | `pg_dump` 逻辑备份（自定义格式） | 每日全量 | 30 天 |
| 附件目录 | 文件系统同步 / 对象存储版本化 | 每日增量 | 30 天 |
| Valkey | **不备份**（会话类数据，丢失可重建） | — | — |
| 配置与密钥 | 由客户密钥管理负责 | 变更时 | 按政策 |

- **RPO**：≤ 24 小时；**RTO**：≤ 4 小时（单实例恢复）。
- 备份文件加密后存放，且与数据库**分离存储**。
- 每季度做一次恢复演练，记录演练结果。
- 备份与数据库一致性：附件与数据库需在同一恢复点，见 [01 附录 A A.6.5](01-技术栈与规范基线.md)。

## 8. 发布与回滚

- **迁移兼容**：采用扩展-收缩模式——先加列/表（向后兼容），再改代码，最后清理旧结构；禁止在单次发布中同时改代码与破坏性 DDL。
- **发布步骤**：备份 → 停应用（或滚动）→ 执行 Flyway → 启动 → 健康检查 → 冒烟验证。
- **回滚**：应用回滚到上一镜像/上一 jar；数据库只做向前修复，不执行 down 迁移。
- **版本标记**：镜像 tag 使用语义版本 + 提交短哈希；`/actuator/info` 暴露版本。
- **发布窗口**：默认可选择停机窗口；单实例部署不做蓝绿。

## 9. 容量与性能基线

| 项 | 基线 |
|---|---|
| 参考规格 | 2 vCPU / 4 GB（应用）+ 2 vCPU / 4 GB（数据库） |
| 预期并发 | 50–100 在线用户 |
| 接口响应 | p95 ≤ 500ms（普通查询），导出类另计 |
| 慢查询阈值 | 200ms，超阈值需给出执行计划说明 |
| 连接池 | HikariCP 默认 10，按并发调整 |
| 分页上限 | 单页 ≤ 100 条（见 03 §9） |

## 10. 部署产物与运维手册

### 10.1 部署产物

| 文件 | 作用 |
|---|---|
| `docker-compose.yml` | 默认部署编排：`web`（Nginx）+ `app` + `postgres` + `valkey` |
| `Dockerfile` | 应用镜像，多阶段构建，运行镜像仅含 JRE 与 jar，非 root 运行 |
| `vane-web/Dockerfile` | 前端构建 + Nginx 托管 admin 与 portal |
| `vane-web/nginx.conf` | 静态托管、`/api/` 反代应用、`/actuator/` 不对外、`/sitemap.xml` 与 `/robots.txt` 反代应用 |
| `.env.example` | 环境变量模板，复制为 `.env` 使用；短信服务需 `VANE_SMS_SECRET_KEYS`（JSON 密钥环）、`VANE_SMS_SECRET_KEY_ACTIVE`（写入版本）、`VANE_SMS_MODE`（`logging` 默认 / `vendor` 接厂商 SDK）与 `VANE_SMS_COST_PER_MESSAGE`（成本估算单价）；群发时段 `VANE_SMS_WINDOW_ENABLED/START/END`，保留期 `VANE_SMS_RETENTION_*_DAYS` |
| `seo.base-url` 系统参数 | 门户对外根地址，部署时必须改为正式域名（canonical 与 sitemap 依赖它） |

### 10.2 运维手册（要点）

| 场景 | 操作 |
|---|---|
| 启动（Compose） | `docker compose up -d`，检查 `docker compose ps` 与健康检查 |
| 启动（裸机） | `java -jar vane-server.jar`，配置经环境变量注入 |
| 查看日志 | `docker compose logs -f app` 或 `logs/app.log` |
| 升级 | 备份 → 替换镜像 tag → 重启 → 健康检查 → 冒烟 |
| 回滚 | 切回上一镜像 tag → 重启 |
| 数据库连接失败 | 检查 PG 状态、连接串、连接池耗尽；查看 `/actuator/health` |
| 登录异常 | 查看 `iam_login_log` 与登录失败计数；确认 Redis/Valkey 可用 |
| 磁盘告警 | 清理应用日志与临时导出文件；检查附件增长 |
| 短信发送失败 | 查看「短信服务 → 发送日志」与 `sys_sms_log.error_code`；检查服务商余额、签名与模板审核状态 |
| 短信密钥轮换 | 在 `VANE_SMS_SECRET_KEYS` 增加新版本并调整 `ACTIVE` → 重启 → 后台逐条「重新加密」→ 确认无旧版本引用后移除旧 key |
| 回执/上行回调 | 回调路径走 Nginx `/api/` 反代，并配置 `limit_req`；核对厂商签名配置与 IP 白名单 |
| 短信数据清理 | 保留期由系统参数控制（日志/回执 180 天、收件人 90 天、上行 180 天），定时任务清理；按号码删除见 ADR-022 |
| 短信回执轮询 | `sms-receipt-poll` 每 10 分钟拉取近 7 天未终结日志的厂商回执（阿里云 QuerySendDetails / 腾讯云 PullSmsSendStatus），Valkey 锁保证单实例；失败下轮重试 |
| 短信告警 | 指标：发送成功率、失败原因分布、回执延迟、上行量、活动进度；告警：失败率超阈值、余额不足、回调验签失败、活动卡住 |
