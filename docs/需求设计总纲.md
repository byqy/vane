## 1. 项目定位与目标

### 1.1 一句话定义

一套**可复制的企业级前后台管理模板**：后台管理端（admin）+ 前台门户端（portal）两端共用一套后端与账号体系；**技术栈锁定到具体版本，接口、国际化、数据、安全、质量门禁均按现行开放标准定义**，可直接作为新项目的起点。

### 1.2 明确不做（非目标）

1. **不做低代码/在线表单设计器**。
2. **不做多租户 SaaS 强制模型**（默认单租户；多站点/多组织用「组织树 + 数据范围」实现）。
3. **不做工作流引擎**（预留扩展点，不内置 BPMN）。
4. **不允许任何配置承载任意 JS/HTML/SQL**——安全边界见分册 06 安全基线。
5. **不做业务领域模型**。

## 2. 范围

### 2.1 两端职责边界

| 端 | 使用者 | 形态 | 职责 |
|---|---|---|---|
| **后台管理端** | 管理员/运营 | 桌面优先 SPA | 系统管理、权限、审计、内容维护、数据导出 |
| **前台门户端** | 普通用户/访客 | 响应式（PC/移动浏览器） | 注册登录、个人中心、公告与内容页、首页区块展示 |
| 共享层 | —— | —— | 后端 API、账号体系、i18n 资源、文件服务、审计 |

## 4. 决策点

全部决策已定；后续变更走 ADR（见 10-ADR）。

| # | 决策 | 结论 |
|---|---|---|
| D-01 | 项目代号 | **`vane`**（风向标）；Java 包 `xyz.byqy.vane.<module>`、groupId `xyz.byqy`、工件 `vane-*`、npm scope `@vane/*` |
| D-02 | 多租户 | 不做多租户 SaaS；单租户 + 组织树 + 数据范围 |
| D-03 | 主键 | UUIDv7，由 PG 18 内置 `uuidv7()` 生成 |
| D-04 | API 版本 | URL 路径主版本 `/api/v1`；仅不兼容变更升主版本；废弃并行期 3 个月；路径分 auth / admin / portal / public |
| D-05 | 响应模型 | 资源式表示 + 真实 HTTP 状态码 + RFC 9457 Problem Details（见 03 §1–§3） |
| D-06 | 前台门户渲染模式 | 纯 SPA（Vue 3 + Vite）+ SEO 基础：URL 语言前缀、动态元数据、服务端 sitemap/robots（见 ADR-017） |
| D-07 | 认证方案 | 不透明令牌：access 15 分钟 + refresh 7 天；refresh 一次性轮换 + 复用检测 + 设备族撤销；refresh 走 `__Host-REFRESH` HttpOnly Cookie（见 03 §14） |
| D-08 | 权限粒度 | RBAC + 数据范围（全部 / 本组织及以下 / 本组织 / 仅本人 / 自定义）；数据范围在查询构建阶段统一注入，表注册 + 显式豁免 + 越权测试（见 02 §2） |
| D-09 | i18n 资源位置 | UI 文案、校验消息、错误码文案放仓库文件；字典、公告、内容页、邮件/短信模板按 locale 存数据库；翻译一期人工，预留 TMS 导入导出（见 04） |
| D-10 | MFA / Passkey | TOTP 一期实现（管理员可选开启、恢复码、防重放、时钟容差）；短信/邮箱与 Passkey 预留（见 03 §14） |
| D-11 | 文件存储 | `FileStorage` 抽象 + 本地磁盘默认 + S3 兼容实现可选；部署按单实例或共享卷（见 02 ADM-09） |
| D-12 | 部署形态 | 默认 Docker Compose（Nginx + 应用 + PostgreSQL + Valkey）；应用为标准可执行 jar，可裸机运行；K8s 不做（见 01 §1） |
| D-13 | 代码生成器 | 不做内置生成器；改为提供完整示例业务模块 + 新增模块 checklist（见 02 ADM-15） |
| D-14 | 主题实现 | 设计令牌 + CSS 变量：`--vane-*` 层映射到 Element Plus 的 `--el-*`；业务样式只用令牌（见 01 §6.4） |
| D-15 | 前端工程形态 | 单仓多包（pnpm workspace）：`packages/shared` + `apps/admin` + `apps/portal`，独立构建与部署（见 01 §4.2） |

## 附录 A：术语表（初版，完整版见分册 11）

| 术语 | 含义 |
|---|---|
| 资源式表示 | 成功响应直接返回资源/集合本身，不用 `{code,msg,data}` 外层包装 |
| Problem Details | RFC 9457 定义的错误响应体结构（`type/title/status/detail/instance` + 扩展成员） |
| `type` URI | Problem Details 中稳定、语言无关的问题类型标识，客户端据此分支 |
| 业务码（`code`） | Problem Details 扩展成员，语言无关的细分标识，如 `IAM.USER.EMAIL_TAKEN` |
| 状态码契约 | 「什么场景返回哪个状态码」的全站唯一口径表，见 03 文档 §3 |
| 版本基线 | 锁定到 patch 的依赖版本清单，唯一权威在分册 01 |
| 许可证门禁 | CI 中阻止 GPL / AGPL / SSPL / RSAL / BUSL 等许可依赖进入产物的检查 |
