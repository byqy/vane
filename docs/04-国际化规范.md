---

核心立场：不是「前端加个语言切换」，而是全链路多语言闭环——界面、校验消息、错误码、邮件与短信模板、字典、时间与数字格式全部覆盖。

## 1. 支持语言

| 项 | 约定 |
|---|---|
| 支持语言 | `zh-CN`、`zh-TW`、`en`、`ja`、`ko`、`ru`、`de`、`fr`、`es`、`pt-BR`、`it`、`nl`、`pl`、`tr`、`uk`、`vi`、`th`、`id`、`ar`、`hi`（共 20 种） |
| 默认语言 | `zh-CN` |
| 语言标签 | BCP 47（RFC 5646）；`pt-BR` 为唯一带地区变体的语言 |
| 书写方向 | `ar` 为 RTL，切换时设置 `document.documentElement.dir`，布局用逻辑属性适配 |
| 回退链 | 精确匹配 → 同语言基础标签（`pt` → `pt-BR`）→ 默认语言 `zh-CN` |
| 新增语言 | 需同时提交前端资源、后端 properties、Element Plus 语言包映射与测试；缺一项不得合并 |

## 2. 资源组织与命名

| 端 | 形式 | 位置 |
|---|---|---|
| 后端 | `messages_<locale>.properties`（UTF-8，地区用下划线，如 `messages_pt_BR.properties`）；`messages.properties` 为中文基础回退 | `vane-common/src/main/resources/i18n/` |
| 前端 | 每语言一个 `locales/<locale>.ts`，由 `i18n.ts` 汇总；语言清单、母语名称、RTL 标记也在该文件 | `packages/shared/src/locales/` |
| 前端页面内帮助 | 每语言一个 `locales/help/<locale>.ts`，合并进 `messages`；键集 `help.<page>.what` / `help.<page>.steps`（见 [ADR-019](10-ADR/ADR-019-页面内帮助.md)） | `packages/shared/src/locales/help/` |
| 前端字段级帮助 | 每语言一个 `locales/help/field/<locale>.ts`，合并进 `messages`；键集 `field.<page>.<field>.help` 与 `fieldHelp.open`（见 [ADR-020](10-ADR/ADR-020-表单字段级帮助.md)） | `packages/shared/src/locales/help/field/` |
| 数据库 | 字典项、公告、内容页、模板按语言存行 | 见 §6 |

**key 命名规则**：

- 语义 key，格式 `module.section.item`，层级不超过 4 层。
- 只允许小写字母、数字、点号：`^[a-z][a-z0-9]*(\.[a-z][a-z0-9]*){1,3}$`。
- **不得**用中文原文当 key；**不得**用序号 key（`text1`、`label2`）。
- 前后端共用同一套 key 命名，同一文案在两端使用相同 key。

页面内帮助（后台菜单页标题旁的「?」）与字段级帮助（表单字段 label 旁的「?」）与界面文案同等对待：
键集合、分条数量、插值占位符在各语言间必须一致；页面标识清单在 `packages/shared/src/help.ts`，
字段清单在 `packages/shared/src/field-help.ts`，门禁见 [ADR-019](10-ADR/ADR-019-页面内帮助.md) 与
[ADR-020](10-ADR/ADR-020-表单字段级帮助.md)。

示例：

```
user.form.email.label
user.form.email.placeholder
validation.email.notUnique
error.IAM.USER.EMAIL_TAKEN
```

## 3. 消息格式

- 统一使用 ICU MessageFormat 语法；前端 `vue-i18n` 与后端 `MessageSource` 均按 ICU 解析。
- 占位符必须命名，禁止位置占位符：`{username}` 而不是 `{0}`。
- 复数与选择必须用 ICU 关键字，不在代码里做字符串拼接：

```
{count, plural, =0 {无记录} one {# 条记录} other {# 条记录}}
{gender, select, male {他} female {她} other {该用户}}
```

- 文案中**不得**拼接句子片段（避免语序差异导致译文错误），整句作为一个 key。

## 4. 语言协商与切换

优先级从高到低：

1. 已登录用户的偏好（存数据库）；
2. URL 语言前缀（前台门户 `/zh-CN/…`、`/en/…`）；
3. 会话或 Cookie（未登录访客）；
4. `Accept-Language`（RFC 4647 lookup）；
5. 默认语言 `zh-CN`。
6. **已登录用户偏好**：用户切换语言时前端写 `iam_user.locale`（`PATCH /auth/me/preferences`），下次登录以服务端偏好初始化界面；异步场景（定时任务、邮件）按收件人 `locale` 渲染，不依赖 `LocaleContextHolder`。

- API 只依赖 `Accept-Language`，并强制 `Vary: Accept-Language`；不通过 URL 前缀切换。
- 用户切换语言后写入偏好；未登录时写 Cookie（`__Host-locale`，`Secure` + `Path=/` + `SameSite=Lax`）。
- 切换语言不改变当前页面的业务数据，只重新渲染文案与格式。
- **语言名称的显示**：表单选项、列表标题等使用「按当前界面语言翻译」的名称（如中文界面下 `en` 显示为「英语」、`zh-CN` 显示为「中文」）；语言切换器保留母语名称（English、简体中文），便于用户找到自己的语言。前端统一用 `languageName(code, uiLocale)`，不直接拼 locale 代码。

## 5. 格式化与本地化

| 类型 | 前端 | 后端 |
|---|---|---|
| 日期和时间 | `Intl.DateTimeFormat` | 本地化 `DateTimeFormatter` |
| 数字 | `Intl.NumberFormat` | `NumberFormat` |
| 货币 | `Intl.NumberFormat` + ISO 4217 | `NumberFormat` + `Currency` |
| 百分比 | `Intl.NumberFormat({style:'percent'})` | `NumberFormat.getPercentInstance` |

- 存储与传输一律 UTC（RFC 3339，见 03 §5）；**展示层**按**客户端时区**（浏览器本地时区）换算，不做服务端时区推断。
- 日期/时间选择器：输入与显示用本地时间（`YYYY-MM-DDTHH:mm:ss`，不带时区），提交前转为 UTC ISO-8601（`toIsoInstant`），回填时由 UTC 转本地（`toDateTimeInput`）；**不得**在本地时间串后直接拼 `Z`。
- 异步场景（邮件、定时任务、报表）需要固定时区时，使用收件人/账号的 IANA 时区（`iam_user.timezone`），不得依赖 `LocaleContextHolder` 或服务器默认时区。
- **时区来源**：登录后前端上报浏览器当前 IANA 时区（`Intl.DateTimeFormat().resolvedOptions().timeZone`），与库中值不同才写入，避免每次登录重复写；浏览器展示始终按当前系统时区，不受库中值影响。
- 用户时区以 IANA 时区 ID（如 `Asia/Shanghai`）表示，不使用固定偏移；浏览器展示取客户端时区，服务端存档值供异步场景使用。
- **不得**手写 `yyyy-MM-dd` 拼接或 `toFixed` 拼货币。

## 6. 内容与模板多语言

| 内容 | 存储方式 |
|---|---|
| 字典项 | `sys_dict_i18n(dict_item_id, locale, label)` |
| 公告 / 内容页 | 正文按 `locale` 分行存储，与业务主表一对多 |
| 邮件 / 短信 / 站内信模板 | 每种语言一条模板 + ICU 变量占位 |

- 模板缺少某语言版本时回退到默认语言，并**记录告警**；不得静默发送空白内容。
- 运营内容允许只提供部分语言，但回退行为必须一致。

## 7. 传输格式归属

- API 中的日期时间、数字、金额格式由 [03 §5](03-HTTP语义与错误模型规范.md) 统一定义，**不随语言变化**（统一 RFC 3339 UTC、十进制字符串）。
- 本地化只发生在展示层；接口不返回已格式化的本地化字符串（除非字段语义本身就是展示文案，如 `title`）。

## 8. 质量门禁

| 检查 | 规则 |
|---|---|
| key 一致性 | 各语言 key 集合必须与 `zh-CN` 完全一致 |
| 缺失 / 多余 | 任一语言缺 key 或有多余 key，构建失败 |
| 占位符一致 | 插值占位符（`{name}`）在各语言中必须相同，由测试校验 |
| 真实翻译 | 非 `en` 语言与英文完全相同的条目超过 20% 即判定未翻译（语言间共用词较多，阈值留余量），测试失败 |
| 硬编码文案 | 静态扫描代码中的中文字符串，命中即失败 |
| 伪语言 | 用 `en-XA` 伪语言跑 UI 测试，检查布局溢出与截断 |
| 未使用 key | 定期扫描并清理，避免资源膨胀 |

## 9. 翻译流程

- 资源文件入仓库，随 PR 评审；新增 key 必须同时提交全部 20 种语言，缺失即构建失败。
- 翻译稿须经母语业务人员复核后入库；可用机器初译辅助，最终以复核结果为准，复核状态记录在 PR 描述中。
- 翻译稿与代码同版本发布，不允许「先上线一种语言、其余后补」。
- 预留第三方 TMS 的导入导出接口，接入时不改动业务代码。








## 10. SEO 本地化

- **URL 是语言的载体**：门户使用 `/{locale}`（首页）、`/{locale}/{slug}`（内容页）、`/{locale}/articles` 与 `/{locale}/articles/{slug}`（文章）；同一内容的不同语言有各自独立 URL，便于搜索引擎分别收录。
- **页面元数据**：标题用「页面标题 - 站点名称」，描述优先取内容的 `summary`，缺失时用站点默认描述；同时写入 Open Graph（`og:title`/`og:description`/`og:type`/`og:url`/`og:image`）与 `twitter:card`。
- **hreflang**：每个页面生成全部支持语言的 `link rel="alternate" hreflang="<locale>"`，与 sitemap 中的 `xhtml:link` 保持一致。
- **canonical**：指向当前语言版本的正式 URL。
- **sitemap**：由后端按「已发布内容 × 全部语言」生成，包含 `lastmod`；更新频率按小时级缓存。
- **静态兜底**：`index.html` 提供默认标题、描述与 `robots`，供不执行 JS 的抓取器读取。
- **错误页**：404 页写 `robots: noindex,follow`，避免无效 URL 被收录。
