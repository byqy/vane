# ADR-020：表单字段级帮助

| 项 | 值 |
|---|---|
| 状态 | 已接受 |
| 日期 | 2026-10-20 |
| 影响文档 | 02 §4、04 §2、08 §8 |
| 关联 | [ADR-019](ADR-019-页面内帮助.md) 的细化；沿用 [ADR-009](ADR-009-国际化资源位置.md)「界面文案入仓库」 |

## 背景

[ADR-019](ADR-019-页面内帮助.md) 用页面级「?」抽屉回答了「这个页面怎么用」，但具体字段仍有坑：
文章 `slug` 改错会让旧链接 404、角色的「数据范围」与「组织授权」是两处配置、定时任务的 cron 是 6 位、
字典编码进网址、导航的文案 key 缺翻译时前台会露原始 key。这些信息在字段所在的表单里才用得上，
翻抽屉或查文档都太远。

现有 placeholder 只能写一行，且输入时消失，承担不了「填错代价高」的说明。

## 决策

1. **字段旁「?」+ 点击气泡**
   - 在 `el-form-item` 的 `label` 插槽里放一个小号「?」按钮，点击打开 `el-popover`（宽 300px，最多 2–3 行）。
   - 不用常驻说明文字：表单会变长，且与 placeholder 重复维护；不用抽屉：字段级说明太短，抽屉过重。
2. **只覆盖填错代价高的字段**
   - 覆盖 33 个字段（导航的文案 key/目标地址/排序、内容页与文章的 slug、分类与标签编码、用户组织与角色、
     角色数据范围、系统参数类型与值、字典编码/名称 key/项值/中文标签、cron/参数/并发、轮播图片/链接/投放窗口、
     邮件模板变量、公告投放窗口）。
   - 判断标准：改错会导致链接失效、越权或看不到数据、任务跑错、安全风险；纯展示性字段不覆盖。
3. **键约定与清单**
   - 键为 `field.<page>.<field>.help`，入口无障碍文案 `fieldHelp.open`。
   - 清单集中在 `packages/shared/src/field-help.ts` 的 `fieldHelpKeys`，`FieldHelp` 的 `help` 属性取该联合类型，
     新增字段漏配时类型检查与测试同时报错。
4. **文案与门禁**
   - 字段级文案单独放 `packages/shared/src/locales/help/field/<locale>.ts`，与页面级文案分文件维护、
     合并进 `messages`；20 种语言全覆盖，键集合、占位符一致（`field-help.test.ts`）。
5. **与页面级帮助分工**
   - 页面级 `HelpTip` 讲流程与页面级注意事项；字段级 `FieldHelp` 只讲这个值填什么。
     同一句话不两处维护：字段级负责细节，页面级不重复。

## 影响

| 项 | 影响 |
|---|---|
| 前端 | 新增 `FieldHelp.vue`；13 个页面的 33 个字段接入 |
| 文案 | 新增 34 个键 × 20 种语言 |
| 测试 | 新增字段级文案门禁与组件测试；既有页面测试回归通过 |
| 文档 | 02 ADM-16 说明扩展；04 增加字段级文案位置；08 组件规范增加 FieldHelp |

## 风险

- 字段级文案与页面级一样会随功能演进而过期，必须与字段变更同批修改。
- popover 在触屏设备需要点击而非悬停，已在组件里固定 `trigger="click"`。
- 字段数增长后 `fieldHelpKeys` 会变长，但仍需保持人工判断「哪些字段值得说明」，避免退化成字段注释。
