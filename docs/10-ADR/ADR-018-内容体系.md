# ADR-018：内容体系（文章 / 分类 / 标签）

| 项 | 值 |
|---|---|
| 状态 | 已接受 |
| 日期 | 2026-10-19 |
| 影响文档 | 02 §4–5、03 §17、04 §10、05 §2、08 §14 |
| 关联 | 与 [ADR-017](ADR-017-门户SEO基础.md) 的 URL 与 sitemap 约定一致 |

## 背景

目标客户是需要持续发布内容的机构。现有 `cms_page` 只适合「关于我们 / 帮助 / 政策」这类单页，
缺少列表型内容所需的能力：分类、标签、发布时间、列表分页与站内搜索。门户需要文章列表、详情与搜索，
后台需要编辑与发布管理。

## 决策

1. **文章独立建模，不与内容页合并**
   - `cms_article` + `cms_article_i18n`：列表型内容，带分类、标签、发布时间与状态机（`DRAFT` → `PUBLISHED` → `ARCHIVED`）。
   - `cms_page` 保持现状，只承担单页。
2. **分类一级**
   - `cms_category` 保留 `parent_id` 字段以备扩展，但业务规则只允许一级（创建时 `parent_id` 必须为空），
     避免在没有多级导航需求时引入树形编辑复杂度。
3. **标签可选、自由创建**
   - `cms_tag` + `cms_article_tag`，保存文章时整体替换标签关联；标签由编辑输入并去重创建。
4. **站内搜索：ILIKE + `pg_trgm`**
   - 匹配当前语言（缺失回退 `zh-CN`）的标题与摘要子串，GIN trigram 索引保证常用规模下的查询性能。
   - 不做分词与相关度排序；数据量到千篇以上再评估 PostgreSQL 全文（需 zhparser）或外部搜索。
5. **正文 HTML 直出**
   - 与 `cms_page` 一致，后台编辑为受信用户；本轮不引入 HTML 白名单过滤。
6. **URL 与 SEO**
   - 门户：`/{locale}/articles`、`/{locale}/articles/{slug}`、`/{locale}/categories/{code}`；
     标签与搜索复用列表页查询参数（`?tag=`、`?keyword=`）。
   - 文章详情按 ADR-017 写标题、描述、canonical、OG、hreflang 与 JSON-LD `Article`；sitemap 纳入已发布文章。
   - 搜索页与分页之外的筛选组合使用 `noindex,follow`，避免索引爆炸。
7. **权限点**：`content:article`、`content:category`、`content:tag` 及对应按钮权限；
   菜单挂在「内容运营」下，排序在公告 / 内容页 / 导航 / 轮播之后。

## 影响

| 项 | 影响 |
|---|---|
| 数据库 | 新增 6 张表与 `pg_trgm` 扩展（迁移 V10） |
| 后台 | 新增文章、分类、标签三个页面与对应接口 |
| 门户 | 新增文章列表、详情、分类筛选与搜索 |
| 测试 | 分类/文章/标签 CRUD、发布可见性、过滤搜索、sitemap 纳入文章 |

## 风险

- 搜索为子串匹配，无相关度排序；内容量增大后需要升级方案。
- 正文直出 HTML 依赖后台编辑可信；若未来开放低权限投稿，需要引入净化与审核流程。
- 分类固定一级，后续要层级时需要迁移与前台导航改造。
