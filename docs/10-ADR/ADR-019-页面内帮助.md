# ADR-019：页面内帮助（标题旁「?」）

| 项 | 值 |
|---|---|
| 状态 | 已接受 |
| 日期 | 2026-10-20 |
| 影响文档 | 02 §4、04 §2、08 §8 |
| 关联 | 遵循 [ADR-009](ADR-009-国际化资源位置.md)「界面文案入仓库」 |

## 背景

后台有 19 个菜单页，有些字段与流程对首次使用者并不直观：导航的「文案 key」要对应语言资源、
文章的 `slug` 决定网址且不宜再改、角色的「组织授权」决定数据范围、定时任务用 6 位 cron 表达式。
现有界面只有字段级 placeholder（一行提示），缺少「这个页面整体怎么用」的说明。

把用法写进外部用户手册有两个问题：与界面不同步、翻不到；目标客户是拿到模板后自行运营的小机构，
通常没有专职培训。帮助必须跟着页面走，并且随界面语言一起切换。

## 决策

1. **入口位置**：每个后台菜单页的标题旁放一个圆形「?」按钮，点击打开右侧抽屉。
2. **内容两段**：固定为「这个页面用来做什么」（一句话）与「怎么用」（3–5 条分条说明），
   抽屉不打断正在填写的表单，比 tooltip / popover 能放更多文字且不遮挡字段。
3. **文案入仓库**：帮助文案属于界面文案，按 [ADR-009](ADR-009-国际化资源位置.md) 放
   `packages/shared/src/locales/help/<locale>.ts`，与基础文案分文件维护后合并进 `messages`；
   键约定 `help.<page>.what`、`help.<page>.steps`，通用键 `help.title` / `help.what` / `help.steps` / `help.open`。
4. **页面标识集中**：`packages/shared/src/help.ts` 的 `helpPages` 是唯一清单，
   `HelpTip` 的 `page` 属性取该联合类型——新增页面漏配文案时类型检查与测试同时报错。
5. **20 种语言全覆盖**：帮助文案与界面文案同一套门禁——键集合一致、无空值、分条数量一致、
   插值占位符一致；缺语言时回退 `zh-CN`，但门禁不允许提交缺键的版本。
6. **与字段提示分工**：帮助只回答「页面整体怎么用」，字段级细节留在 placeholder，
   避免同一句话在两处维护（[08 §10](08-前端架构与设计系统.md)）。

## 影响

| 项 | 影响 |
|---|---|
| 前端 | 新增 `HelpTip.vue` 组件与 `help.ts` 文案约定；19 个后台页面标题接入 |
| 文案 | 新增 4 条通用键 + 19×2 条页面键，覆盖 20 种语言 |
| 测试 | 新增帮助文案门禁测试与组件测试 |
| 文档 | 02 增加功能条目；04 说明帮助文案同属界面文案；08 记录组件约定 |

## 风险

- 帮助文案会随功能演进而过期：字段或流程变更时必须同步修改帮助文案，否则会误导用户；
  页面接入与文案键由类型和测试约束，但「内容是否仍然正确」仍需代码评审把关。
- 帮助文案量增大后（页面增多）单文件会变长，必要时按业务域再拆分 help 文案文件。
- 抽屉在小屏上占满宽度，移动端后台不在本期范围（后台桌面优先）。
