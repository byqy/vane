# ADR-023：审计日志精细化（目标级 + 关键操作字段级）

| 项 | 值 |
|---|---|
| 状态 | 已接受 |
| 日期 | 2026-10-21 |
| 影响文档 | 02 §4、03 §19、05 §5.6 §9、06 §9、07 §10、08 §16、09 §14 |
| 关联 | 沿用 [ADR-005](ADR-005-响应模型.md) 的审计只增约定；与登录日志（`iam_login_log`）互补 |

## 背景

操作日志目前由 `@Audit` 注解 + `AuditAspect` 实现：记录操作人快照、`module`、`action`、
HTTP 方法/路径、入参 JSON（按字段名正则脱敏）、结果、错误码、耗时、IP、`traceId`、时间，
全仓 66 处注解，覆盖主要写接口。

它回答「谁在何时调了什么接口、成功没有」，但回答不了：

- 操作的是**哪个对象**（没有 `target_type/target_id`，只能翻参数）；
- **改前是什么、改后是什么**（只记入参，旧值不在日志里）；
- 批量导入/导出**影响多少条**（只有一行日志与大 JSON）；
- 请求的 **HTTP 状态、UA、操作者组织**；
- 数据导出/文件下载**是否发生、带走了什么范围**（导出接口未纳入审计）；
- 审计记录本身**防篡改**（应用账号仍有 UPDATE/DELETE 权限）。

## 决策

### 1. 分层与范围

| 层级 | 内容 | 本期 |
|---|---|---|
| L1 目标级 | 所有 `@Audit` 操作增加目标对象、HTTP 状态、UA、组织、批量影响条数 | 做 |
| L2 字段级 | 仅关键实体记录 `before/after` 变更（白名单） | 做 |
| L3 数据级历史 | 任意时点回放（Envers/历史表） | **不做**，另立 ADR 评估 |
| L4 防篡改 | 应用账号 `sys_oper_log` 只插/只读；保留期由**外部运维脚本**清理 | 做 |

**审计对象**：仅「经管理 API 的用户写操作」进 `sys_oper_log`（`source=API`）。
定时任务继续写 `sys_job_log`（含影响条数摘要）；**仅破坏性任务**（保留期清理、取消群发）
额外写一条 `sys_oper_log`（`source=JOB`、操作人 `SYSTEM`、target 为任务/资源、`affectedCount`）。
自动退订不写操作日志——`sys_sms_inbound` + `sys_sms_optout` 记录本身即证据。

`source` 取值：`API`（默认）、`JOB`、`SYSTEM`。

### 2. 注解扩展

```java
@interface Audit {
    String module();
    String action();
    String targetType() default "";   // 如 user、role、config、sms-provider
    String targetId() default "";     // SpEL：#id、#p0；解析失败只记空
    String targetLabel() default "";  // SpEL：可读快照，如 #request.username
    boolean detail() default false;   // 允许 service 通过 AuditContext 上报字段级变更
}
```

- 未标注 `targetType` 的旧注解继续工作（等价 L0）。
- `detail=true` 仅用于 L2 白名单方法；未上报变更时仍写 L1 行。
- 目标 SpEL 使用方法入参求值；兼容 `#p0`，参数名依赖 `-parameters`（项目已开启）。

### 3. 变更采集：`AuditContext` + `AuditDiff`

- 切面调用前打开 `AuditContext`（ThreadLocal），**finally 清理**，避免线程池串请求。
- service 在**同一事务内**读取旧值、执行更新，并调用
  `AuditContext.record(before, after)` / `recordCreated(after)` / `recordDeleted(before)`；
  只上报白名单字段。旧值必须在更新前读取。
- 切面只在 `result=SUCCESS` 时写 `changes`；`FAIL` 只写目标与入参（避免事务回滚后
  审计显示未发生的变更）。
- `AuditDiff` 负责：扁平化 `a.b.c` 路径、只保留变化字段、掩码、上限 100 字段 / 16KB，
  超出置 `changes_truncated=true`。
- `changes=[]` 表示「已采集且无变化」；`changes=null` 表示「未采集」。
- 批量/导入/导出通过 `AuditContext.setAffectedCount(int)` 上报影响条数。

L2 覆盖清单（本期）：

| 模块 | 动作 | 记录字段（示例） |
|---|---|---|
| user | create / update / delete / reset-password / assign-roles | username、nickname、email、status、deptId、roles（密码/令牌恒 `***`） |
| auth | password（自助改密）/ mfa-bind / mfa-confirm / mfa-disable | email、mfaEnabled 前后值；密码、MFA 密钥、恢复码恒 `***` |
| role | create / update / delete / assign-permissions / assign-depts | code、name、dataScope、permissionCodes、deptIds |
| config | update | key、旧值、新值（`valueJson` 内嵌敏感键只记键名） |
| sms | update-provider | name、countries、enabled、isDefault、config 的**键名**；密钥值恒 `***` |
| sms | replace-bindings | templateId、绑定条目数、变更的 provider/country/locale 组合 |
| sms | start/pause/cancel-campaign | status 前后值 |

内容发布/下线、文件删除等只做 L1（对象 + 结果），不做字段级。

### 4. 脱敏

- 键名规则：包含 `password / secret / token / accesskey / secretkey / callbacktoken /
  code / recoverycode` 的字段值恒为 `***`，`before/after` 均不落明文。
- **字符串化 JSON 必须递归解析**：`params`、`changes`、系统参数 `valueJson`、服务商
  `config` 等字段若值是 JSON 字符串，解析后再按同一规则脱敏；解析失败则整体 `***`。
- `config` / `valueJson` 类字段采用「只记键名、值恒 `***`」的显式策略，不依赖正则命中。
- 值规则：手机号（E.164 与国内 11 位）、邮箱、身份证号按「保留首尾」掩码；
  规则可通过 `vane.audit.mask-value-patterns` 配置。
- 入参 `params` 上限 **8KB**（序列化前按字段/大小预算裁剪），超出写
  `{"__truncated__":true}`；`user_agent` 截断 512。
- CSV 导出的 `params`/`changes` 单元格截断 4KB 并走同一脱敏管道。

### 5. 数据模型（迁移 V16）

`sys_oper_log` 增加列：

| 列 | 类型 | 说明 |
|---|---|---|
| `source` | text | `API` / `JOB` / `SYSTEM`，默认 `API` |
| `target_type` | text | 目标类型，如 `user`、`role`、`sms-provider` |
| `target_id` | text | 目标标识（UUID 或业务键），统一字符串 |
| `target_label` | text | 目标可读快照（如用户名、角色名） |
| `http_status` | smallint | 响应状态；由拦截器在响应完成后回填，无法取得时为空 |
| `user_agent` | text | 截断 512 |
| `dept_id` | uuid | 操作者所属组织快照（数据范围） |
| `affected_count` | integer | 批量/导入/导出影响条数 |
| `changes` | jsonb | `[{"field":"status","before":"ACTIVE","after":"DISABLED"}]` |
| `changes_version` | smallint | 变更格式版本，当前 `1` |
| `changes_truncated` | boolean | 变更超限截断标记，默认 false |

索引：`idx_sys_oper_log_target (target_type, target_id, created_at desc)`、
`idx_sys_oper_log_trace (trace_id)`；保留既有时间与用户索引。

V16 只加列与索引，**不注册清理任务**（清理见 §8）。

### 6. 导出/下载纳入审计

所有 CSV 导出与文件下载加 `@Audit(module, action="export"|"download", targetType=...)`：

| 接口 | module / action | affected_count |
|---|---|---|
| 操作日志导出 | `audit` / `export` | 导出行数 |
| 登录日志导出 | `audit` / `export` | 导出行数 |
| 用户列表导出 | `user` / `export` | 导出行数 |
| 短信错误行导出 | `sms` / `export` | 导出行数 |
| 文件下载 | `file` / `download` | 1（目标为文件 ID） |

导出动作自身也写操作日志（审计闭环），但不记录导出文件内容。

### 7. 查询与详情接口（03 §19）

- `GET /api/v1/admin/oper-logs`：新增过滤 `source`、`targetType`、`targetId`、`traceId`、
  `ip`、`httpStatus`；**`targetId` 必须与 `targetType` 同时使用**（复合索引）。
  列表项不返回 `params`/`changes`，返回目标、状态、UA、组织、影响条数等摘要字段。
- `GET /api/v1/admin/oper-logs/{id}`：详情返回完整 `params` 与 `changes`，权限点
  `audit:oper-log:detail`（新增）；不存在 404。
- 导出 CSV 增加目标、变更、HTTP 状态、UA、影响条数列；上限 5000 行，单元格做截断。
- 登录日志接口保持现状（`iam_login_log` 已含 UA 与细分失败结果）。

### 8. 保留与防篡改

- 保留期默认 **730 天**（不低于等保建议的 6 个月），操作日志与登录日志**都**按此清理。
- 清理由**部署侧维护脚本**（cron + psql）执行，使用独立维护账号；应用不注册清理任务，
  应用账号对 `sys_oper_log` 仅授予 `INSERT / SELECT`，对 `iam_login_log` 同样只插只读。
  运维手册（07 §10）给出脚本与保留期参数；清理前按备份策略归档。
- 哈希链/WORM 归档不在本期；需要时另立 ADR。

### 9. 一致性与状态采集

- 审计写入保持**同步**（调用结束后写一行）；批量操作只写摘要行，不逐条写。
- 审计写入失败仅告警，不影响业务（当前取向；高风险操作 fail-closed 留待后续按需配置）。
- `http_status` 由 `HandlerInterceptor.afterCompletion`（或等效 Filter）在响应完成后回填；
  切面写行时先置空，回填时 HTTP 状态已确定。无法取得（如连接中断）时保持空。
- 记录语义为「尝试」：业务成功但响应阶段失败时 `result=SUCCESS`、`http_status` 可能为 5xx；
  回滚由 `result=FAIL` + 错误码体现，且不写 `changes`。

## 后果

- 正向：能直接回答「谁把哪个对象的哪个字段从什么改成什么」，导出/下载可追溯，
  查询可按目标与 trace 串联；审计不可篡改与保留策略不再互相矛盾。
- 成本：`changes` 带来存储增长（已限 100 字段/16KB）；L2 需要在 service 显式上报，
  新增实体时要补白名单；脱敏需递归处理。
- 不做 L3 的代价：无法回放未被白名单覆盖的字段；需要时按 ADR 另行评估 Envers。

## 备选（未选）

| 备选 | 不选原因 |
|---|---|
| Hibernate Envers 全表历史 | 依赖与存储成本高、覆盖所有写路径；先以白名单 L2 满足管理端查询 |
| 数据库触发器写历史表 | 拿不到操作人/请求上下文与业务动作语义 |
| CDC（Debezium） | 超出部署形态（Compose 单机）与范围 |
| 哈希链防篡改 | 本期只做只插权限；合规要求明确后再立项 |
| 应用内清理任务 | 与「应用账号只插」冲突；改为部署侧维护脚本 |

## 测试

- 单元：`AuditDiff`（新增/删除/变更、嵌套路径、白名单、100 字段/16KB 截断、
  `changes=[]` 与 `null` 语义）、`AuditMasker`（键名/值规则、递归 JSON、密钥恒空）、
  目标 SpEL 解析失败降级、UA 截断、`setAffectedCount`。
- 集成：用户更新产生 `targetId` 与 `changes`；角色授权记录权限码前后差异；
  系统参数更新旧值/新值且 `valueJson` 内密钥不落明文；短信服务商密钥只出现 `***`；
  改密/MFA 启停写入审计且密钥/密码不出现；导出接口写 `action=export` 且
  `affected_count` 正确；列表按目标/trace 过滤且不含 `params/changes`；详情返回
  `changes` 且需 `audit:oper-log:detail`；失败回滚不写 `changes`；清理脚本按保留期删除
  操作日志与登录日志。
- 契约：导出不泄露敏感值；详情权限与 404；审计记录不含密码/令牌/MFA 密钥。

## 实施顺序

1. V16 迁移、实体与查询扩展（含 `source`/`changes_version`/索引）；
2. 注解扩展与 `AuditContext`/`AuditDiff`/`AuditMasker`；
3. 用户/角色/参数/短信/自助认证的 L2 上报；
4. 导出/下载审计与 `affected_count`；
5. 拦截器回填 `http_status`；
6. 前端列表、详情抽屉、导出格式；
7. 清理维护脚本与运维文档；
8. 测试与覆盖率。
