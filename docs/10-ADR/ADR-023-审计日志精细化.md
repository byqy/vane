# ADR-023：审计日志精细化（目标级 + 关键操作字段级）

| 项 | 值 |
|---|---|
| 状态 | 已接受 |
| 日期 | 2026-10-21 |
| 影响文档 | 02 §4、03 §19、05 §5.6 §9、06 §9、07 §10、08 §16、09 §3 |
| 关联 | 沿用 [ADR-005](ADR-005-响应模型.md) 的审计只增约定；与登录日志（`iam_login_log`）互补 |

## 背景

操作日志目前由 `@Audit` 注解 + `AuditAspect` 实现：记录操作人快照、`module`、`action`、
HTTP 方法/路径、入参 JSON（按字段名正则脱敏）、结果、错误码、耗时、IP、`traceId`、时间，
全仓 66 处注解，覆盖主要写接口。

它回答「谁在何时调了什么接口、成功没有」，但回答不了：

- 操作的是**哪个对象**（没有 `target_type/target_id`，只能翻参数）；
- **改前是什么、改后是什么**（只记入参，旧值不在日志里）；
- 批量导入/导出**影响多少条**（只有一行日志与大 JSON）；
- 请求的 **HTTP 状态、UA、操作者组织**；
- 数据导出/文件下载**是否发生、带走了什么范围**（导出接口未纳入审计）；
- 审计记录本身**防篡改**（应用账号仍有 UPDATE/DELETE 权限）。

## 决策

### 1. 分层：做 L1 + 关键操作 L2

| 层级 | 内容 | 本期 |
|---|---|---|
| L1 目标级 | 所有 `@Audit` 操作增加目标对象、HTTP 状态、UA、组织、批量影响条数 | 做 |
| L2 字段级 | 仅关键实体记录 `before/after` 变更（白名单） | 做 |
| L3 数据级历史 | 任意时点回放（Envers/历史表） | **不做**，另立 ADR 评估 |
| L4 防篡改 | 只插权限 + 保留期归档；哈希链/WORM | 只做「只插 + 保留期」 |

L3 不做的理由：全表历史会给所有写路径增加历史表与存储成本，需先明确「哪些表需要回放」
与保留期；`before/after` 已覆盖管理端最常问的「谁把什么改成了什么」。

### 2. 注解扩展

```java
@interface Audit {
    String module();
    String action();
    String targetType() default "";   // 如 user、role、config、sms-provider
    String targetId() default "";     // SpEL：#id、#request.userId
    String targetLabel() default "";  // SpEL：可读快照，如 #request.username
    boolean detail() default false;   // 允许 service 通过 AuditContext 上报字段级变更
}
```

- 目标 SpEL 在方法入参上求值（`#p0` / 参数名）；解析失败只记空，不影响主流程。
- 未标注 `targetType` 的旧注解继续工作（等价 L0）。
- `detail=true` 仅用于 L2 白名单方法；未上报变更时仍写 L1 行。

### 3. 变更采集：`AuditContext` + `AuditDiff`

- 切面在调用前打开 `AuditContext`（ThreadLocal），调用后关闭。
- service 在事务内调用 `AuditContext.record(before, after)` 或 `recordCreated(after)` /
  `recordDeleted(before)`，只上报**白名单字段**。
- `AuditDiff` 负责：字段级比较（扁平化 `a.b.c` 路径）、只保留变化字段、按字段掩码、
  上限 100 个字段 / 16KB，超出置 `changes_truncated=true`。
- 切面统一写一行 `sys_oper_log`：`changes` 来自上下文，`params` 仍为入参快照。

L2 覆盖清单（本期）：

| 模块 | 动作 | 记录字段（示例） |
|---|---|---|
| user | create / update / delete / reset-password / assign-roles | username、nickname、email、status、deptId、roles（密码/令牌永远 `***`） |
| role | create / update / delete / assign-permissions / assign-depts | code、name、dataScope、permissionCodes、deptIds |
| config | update | key、旧值、新值（`valueJson` 超长截断） |
| sms | update-provider | name、countries、enabled、isDefault、config 的**键名**；密钥值恒为 `***` |
| sms | replace-bindings | templateId、绑定条目数、变更的 provider/country/locale 组合 |
| sms | start/pause/cancel-campaign | status 前后值 |

内容发布/下线、文件删除等只做 L1（对象 + 结果），不做字段级。

### 4. 脱敏

- 键名规则（沿用并扩展）：包含 `password / secret / token / accesskey / secretkey /
  callbacktoken / code` 的字段值恒为 `***`，`before/after` 均不落明文。
- 值规则：手机号（E.164 与国内 11 位）、邮箱、身份证号按「保留首尾」掩码；
  规则可通过 `vane.audit.mask-value-patterns` 配置。
- 入参 `params` 上限 **8KB**，超出写 `{"__truncated__":true}`；`changes` 上限见上。
- `user_agent` 截断 512 字符。

### 5. 数据模型（迁移 V16）

`sys_oper_log` 增加列：

| 列 | 类型 | 说明 |
|---|---|---|
| `target_type` | text | 目标类型，如 `user`、`role`、`sms-provider` |
| `target_id` | text | 目标标识（UUID 或业务键），统一字符串 |
| `target_label` | text | 目标可读快照（如用户名、角色名），只读展示 |
| `http_status` | smallint | 响应状态；异常未生成响应时为空 |
| `user_agent` | text | 截断 512 |
| `dept_id` | uuid | 操作者所属组织快照（数据范围） |
| `affected_count` | integer | 批量/导入/导出影响条数 |
| `changes` | jsonb | `[{"field":"status","before":"ACTIVE","after":"DISABLED"}]` |
| `changes_truncated` | boolean | 变更超限截断标记 |

索引：`idx_sys_oper_log_target (target_type, target_id, created_at desc)`、
`idx_sys_oper_log_trace (trace_id)`；保留既有时间与用户索引。

迁移脚本 `V16__audit_detail.sql`（计划）：加列、加索引、登记 `audit-retention` 清理任务
（每日 03:30，保留期默认 **730 天**，`vane.audit.retention-days` 可配）。

### 6. 导出/下载纳入审计

所有 CSV 导出与文件下载加 `@Audit(module, action="export"|"download", targetType=...)`：

| 接口 | module / action | affected_count |
|---|---|---|
| 操作日志导出 | `audit` / `export` | 导出行数 |
| 登录日志导出 | `audit` / `export` | 导出行数 |
| 用户列表导出 | `user` / `export` | 导出行数 |
| 短信错误行导出 | `sms` / `export` | 导出行数 |
| 文件下载 | `file` / `download` | 1（目标为文件 ID） |

导出动作自身也写操作日志（审计闭环），但不记录导出文件内容。

### 7. 查询与详情接口（03 §19）

- `GET /api/v1/admin/oper-logs`：新增过滤 `targetType`、`targetId`、`traceId`、`ip`、
  `httpStatus`；**列表项不返回 `params`/`changes`**（控制响应体积），返回目标、状态、
  UA、组织、影响条数等摘要字段。
- `GET /api/v1/admin/oper-logs/{id}`：详情返回完整 `params` 与 `changes`（仍需
  `audit:oper-log` 权限）；不存在返回 404。
- 导出 CSV 增加目标、变更、HTTP 状态、UA、影响条数列；导出上限沿用 5000 行。
- 登录日志接口保持现状（`iam_login_log` 已含 UA 与细分失败结果）。

### 8. 保留与防篡改

- 保留期默认 730 天（等保建议不少于 6 个月，取 2 年），由 `audit-retention` 任务清理；
  清理前由运维归档（07 §10），不做应用内硬删除接口。
- 应用数据库账号对 `sys_oper_log` 仅授予 `INSERT` 与 `SELECT`，不授予 `UPDATE/DELETE`
  （部署脚本与运维手册登记；迁移/清理使用独立账号）。
- 哈希链/WORM 归档不在本期；需要时另立 ADR（会改变表结构与写入路径）。

### 9. 异步与一致性

- 审计写入保持**同步**（调用结束后写一行），保持与请求顺序一致；批量操作只写摘要行，
  不逐条写。
- 审计写入失败仅告警，不影响业务（沿用现状）。
- 记录语义为「尝试」：业务成功但响应阶段失败时 `result=SUCCESS` 而 `http_status` 可能为空；
  回滚由 `result=FAIL` + 错误码体现。

## 后果

- 正向：能直接回答「谁把哪个对象的哪个字段从什么改成什么」，导出/下载可追溯，
  查询可按目标与 trace 串联。
- 成本：`changes` 带来存储增长（已限 100 字段/16KB）；L2 需要在 service 显式上报，
  新增实体时要补白名单；脱敏规则需评审。
- 不做 L3 的代价：无法回放未被白名单覆盖的字段；需要时按 ADR 另行评估 Envers。

## 备选（未选）

| 备选 | 不选原因 |
|---|---|
| Hibernate Envers 全表历史 | 依赖与存储成本高、覆盖所有写路径；先以白名单 L2 满足管理端查询 |
| 数据库触发器写历史表 | 拿不到操作人/请求上下文与业务动作语义 |
| CDC（Debezium） | 超出部署形态（Compose 单机）与范围 |
| 哈希链防篡改 | 本期只做只插权限；合规要求明确后再立项 |

## 测试

- 单元：`AuditDiff`（新增/删除/变更、嵌套路径、白名单、截断）、`AuditMasker`
  （键名/值规则、密钥恒空）、SpEL 目标解析失败降级。
- 集成：用户更新产生 `targetId` 与 `changes`；角色授权记录权限码前后差异；
  系统参数更新旧值/新值；短信服务商密钥只出现 `***`；导出接口写 `action=export`
  且 `affected_count` 正确；列表按目标/trace 过滤；详情返回 `changes`、列表不返回；
  清理任务按保留期删除旧行。
- 契约：导出不泄露敏感值；详情接口权限与 404；审计记录不含密码/令牌。

## 实施顺序

1. V16 迁移与实体/查询扩展；2. 注解与 `AuditContext`/`AuditDiff`/`AuditMasker`；
3. 用户/角色/参数/短信 L2 上报；4. 导出/下载审计；5. 前端列表与详情抽屉；
6. 清理任务与运维文档；7. 测试与覆盖率。
