# ADR-027：仓库主从关系调整（GitHub 主仓、Gitee 镜像）

| 项 | 值 |
|---|---|
| 状态 | 已接受 |
| 日期 | 2026-10-27 |
| 影响文档 | `README.md`、`CONTRIBUTING.md`、`.github/ISSUE_TEMPLATE/config.yml`、`docs/README.md`、总纲 §3 |
| 关联 | 取代 [ADR-026](ADR-026-开源许可与仓库发布.md) 决策 2 中的仓库主从关系；ADR-026 的许可证（MIT）与发布前清理要求**继续有效** |

## 背景

ADR-026 决策 2 曾定为「Gitee 主仓、GitHub 只读镜像」。实施时确认了两个平台机制差异：

1. **Gitee 的「仓库镜像管理」只支持从 GitHub/GitLab 等外部平台拉取到 Gitee**，不支持反向推送；Gitee 主仓时 GitHub 镜像必须靠本地脚本或 Gitee Go 流水线主动推送，链路更长、更容易滞后。
2. **GitHub 拥有更完整的协作与自动化生态**：Actions、Dependabot、Issue/PR 模板、代码扫描均原生可用；Gitee 不提供等价能力（Gitee Go 另需配置）。
3. 公开模板项目的使用者以检索 GitHub 为主，主仓在 GitHub 更利于被发现与引用。

## 决策

1. **GitHub 为主仓（`origin`）**
   - Issue 与 Pull Request 统一在 GitHub 受理。
   - CI 使用 GitHub Actions（`.github/workflows/ci.yml`），Dependabot 在 GitHub 侧运行。
2. **Gitee 为只读镜像**
   - 使用 Gitee 仓库的「仓库镜像管理 → 从 GitHub 拉取」自动同步，无需自建推送脚本或流水线。
   - 镜像仓在 Gitee 上关闭 Issue 与 Pull Request，页面明确「以 GitHub 为准」。
3. **保留 ADR-026 的其余结论**
   - 许可证仍为 MIT；发布前清理与必备文件清单不变；示例凭据的标注要求不变。

## 影响

| 项 | 影响 |
|---|---|
| 仓库 | 远程命名：`origin` = GitHub，`gitee` = 镜像；日常只需 `git push origin`，Gitee 由平台自动同步 |
| 文档 | `README.md`、`CONTRIBUTING.md`、Issue 模板链接、`docs/README.md` 与总纲的 ADR 计数同步 |
| 流程 | 贡献入口收敛到 GitHub；Gitee 侧仅提供国内访问加速 |
| 风险 | 国内访问 GitHub 不稳定时体验下降（镜像可缓解阅读，但贡献需跳转）；镜像同步存在延迟，需在 README 标注 |

## 风险与取舍

- **贡献门槛**：国内贡献者可能需要代理才能提 Issue/PR；若后续贡献者主要来自国内，应重新评估主从关系（另立 ADR），而不是两边同时受理。
- **镜像延迟**：Gitee 拉取为定时同步，紧急修复后 Gitee 侧可能短暂落后；README 已声明以 GitHub 为准。
- **双平台数据不一致**：镜像仓的 Issue/PR 关闭，避免出现无法合并的贡献。
