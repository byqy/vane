# ADR-022：短信服务（配置、发送、群发、回执与上行）

| 项 | 值 |
|---|---|
| 状态 | 已接受 |
| 日期 | 2026-10-20 |
| 影响文档 | 01 §2.2、02 §4、03 §18、05 §5.8、07 §10、08 §15、09 §13 |
| 关联 | 沿用 [ADR-009](ADR-009-国际化资源位置.md)「内容入数据库、界面文案入仓库」；与消息模板（`sys_message_template`）共用模板与 i18n 机制 |

## 背景

现有消息能力只有邮件：`sys_message_template` 已支持 `EMAIL / SMS / INAPP` 三种频道，
`MailPort` + `MailDispatcher` 用端口-适配器方式对接 SMTP，SMTP 未配置时降级为日志。
短信缺的是一整条链路：服务商配置、密钥管理、签名、厂商模板映射、发送日志、频控、
群发、送达回执、用户上行（退订）与国际号码支持。

短信与邮件不同：号码与模板必须在服务商侧报备、按国家/地区有独立规则、按条计费、
营销短信有退订与发送时段要求，因此需要独立的配置与管理界面，而不是复用邮件配置。

## 决策

1. **服务商与 SDK**
   - 一期接入阿里云与腾讯云，使用官方 Java SDK（`com.aliyun:alibabacloud-dysmsapi20170525`、
     `com.tencentcloudapi:tencentcloud-sdk-java-sms`）；两者许可证均为 Apache-2.0，
     具体版本在 P1 实施时锁定并登记 [01 §2.2](../01-技术栈与规范基线.md)。
   - 抽象 `SmsPort`（发送、查询回执、拉取上行）作为业务唯一出口，厂商实现放基础设施层。
   - 预留 `GenericHttpSmsPort`（可配置 URL/Headers/签名的 HTTP 网关）作为扩展点，
     用于自建网关或未提供 SDK 的服务商；一期不实现。
2. **配置与密钥**
   - 服务商配置存 `sys_sms_provider.config_cipher`，AES-GCM 加密；主密钥来自环境变量
     `VANE_SMS_SECRET_KEY`，缺失时启动告警并禁止保存服务商配置。
   - 记录 `key_version`，支持密钥轮换（新写入用新版本，旧数据读取时按版本解密）。
   - 查询接口只回显掩码（如 `LTAI****abcd`），写接口不接受回显值回写；日志与错误 detail 不出现密钥。
3. **模板与签名**
   - 站内模板继续用 `sys_message_template`（channel=`SMS`）与 `sys_message_template_i18n`，
     正文支持 `{变量}`；新增 `sys_sms_template_binding` 关联「站内模板 → 服务商模板码 + 签名 + 变量映射」，
     绑定按 `provider_code + country_code + locale` 维度（各国模板码与签名不同）。
   - 签名单独维护（`sys_sms_signature`），按服务商 + 国家 + 语言，带启停状态。
4. **发送路径**
   - 业务调用 `SmsService.send(scene, phone, locale, variables)`：号码规范化（E.164）→ 频控 →
     渲染模板 → 解析绑定 → `SmsPort.send` → 写 `sys_sms_log`。
   - 超时：连接 2 秒、读取 5 秒；仅对网络错误与厂商限流做指数退避重试（最多 2 次）。
   - 厂商错误码映射为内部错误码（`SMS.PROVIDER_REJECTED` / `SMS.PROVIDER_TIMEOUT` /
     `SMS.RATE_LIMITED` 等），按 03 的 Problem Details 返回。
   - 未配置服务商时降级为 `LoggingSmsPort`（记录日志不发送），与邮件未配置 SMTP 的处理一致。
5. **群发营销（几万级）**
   - 不引入 MQ（`docs/01` 范围外），用数据库队列：`sys_sms_campaign` + `sys_sms_recipient`。
   - worker 由定时任务触发（复用现有任务框架），Valkey 分布式锁保证单实例执行；
     每批 200 条、限速可配（如 100 条/秒），状态机 `DRAFT → SCHEDULED → RUNNING → PAUSED / DONE / CANCELLED`。
   - 导入支持 CSV 与按用户筛选；导入时号码规范化、去重、过滤退订与黑名单；失败按错误类型退避重试。
   - 发送前统一过滤 `sys_sms_optout`；营销模板必须为已审核模板，按接收方时区限制发送时段。
6. **回执与上行**
   - 回执：统一 `delivery_status`（`PENDING / DELIVERED / FAILED / UNKNOWN`），
     定时任务轮询近 48 小时未终态记录（阿里云 `QuerySendDetails`、腾讯云状态查询），
     并提供可选回调端点（校验厂商签名/时间戳、IP 白名单、按厂商消息 ID 幂等）。
   - 上行：厂商回调或定时拉取用户回复，写入 `sys_sms_inbound`；按国家维护退订关键词
     （如 `TD`、`退订`、`STOP`），命中后写入 `sys_sms_optout`（范围默认「仅营销」）。
   - 回执（送达状态）与上行（用户回复）是两件事，分别由 `sys_sms_log.delivery_status` 与
     `sys_sms_inbound` 承载。
7. **国际号码**
   - 号码统一按 E.164 存储并规范化，解析用 `com.googlecode.libphonenumber:libphonenumber`（Apache-2.0）。
   - 一期支持范围：中国大陆、香港、澳门、台湾、东南亚（SG/MY/TH/VN/ID/PH 等），
     以国家白名单配置；不在白名单的号码在导入与发送时拒绝。
   - 按国家/地区路由服务商与账号（`sys_sms_provider` 配置国家范围），国际短信使用服务商国际站能力。
   - 合规提示：美国 10DLC、印度 DLT 等注册由客户自行完成，模板不代办，只在界面与文档提示。
8. **管理入口与权限**
   - 独立菜单「运维管理 → 短信服务」，子页：服务商配置、签名、模板绑定、发送日志、群发任务、退订名单。
   - 权限点：`ops:sms`（菜单）、`ops:sms:config`、`ops:sms:template`、`ops:sms:log`、`ops:sms:campaign`、`ops:sms:send`。
   - 配置变更、测试发送、群发启停、手动重发均写审计日志。

## 数据模型（迁移 V12）

| 表 | 关键列 | 说明 |
|---|---|---|
| `sys_sms_provider` | `provider_code`(唯一)、`provider_type`、`name`、`config_cipher`、`key_version`、`countries`(jsonb)、`enabled`、`is_default`、审计四列 | 服务商配置 |
| `sys_sms_signature` | `provider_code`、`sign_name`、`country_code`、`locale`、`status` | 短信签名 |
| `sys_sms_template_binding` | `template_id` → `sys_message_template`、`provider_code`、`provider_template_code`、`signature_id`、`country_code`、`locale`、`param_mapping`(jsonb) | 模板与变量映射 |
| `sys_sms_log` | `template_code`、`phone_masked`、`phone_hash`、`country_code`、`provider_code`、`provider_message_id`、`campaign_id`、`result`、`delivery_status`、`delivered_at`、`error_code`、`duration_ms`、`trace_id`、`receipt_raw`(jsonb) | 发送记录（事务 + 群发） |
| `sys_sms_campaign` | `name`、`template_id`、`provider_code`、`signature_id`、`status`、`scheduled_at`、`throttle_per_second`、`total`、`sent`、`failed`、审计四列 | 群发活动 |
| `sys_sms_recipient` | `campaign_id`、`phone_e164`、`country_code`、`params`(jsonb)、`status`、`provider_message_id`、`error_code`、`attempts`、`sent_at` | 群发收件人 |
| `sys_sms_optout` | `phone_hash`、`scope`(`ALL`/`MARKETING`)、`source`(`MANUAL`/`INBOUND`)、`reason`、`created_at` | 退订与黑名单 |
| `sys_sms_inbound` | `provider_code`、`provider_message_id`、`phone_masked`、`phone_hash`、`content`、`received_at`、`processed`、`matched_keyword` | 上行消息原文 |

索引：`sys_sms_log(provider_message_id)`、`sys_sms_log(created_at desc)`、
`sys_sms_recipient(campaign_id, status)`、`sys_sms_optout(phone_hash)`、
`sys_sms_inbound(processed, received_at)`。

| GET | `/logs/export` | 导出 CSV（`ops:sms:log`） |
| POST | `/logs/{id}/resend` | 手动重发（`ops:sms:send`） |
| GET/POST/PATCH | `/campaigns` | 群发活动（`ops:sms:campaign`） |
| POST | `/campaigns/{id}/start`、`/pause`、`/resume`、`/cancel` | 状态流转（`ops:sms:campaign`） |

| GET/POST/DELETE | `/optouts` | 退订名单维护（`ops:sms:log`） |

## 错误码

`SMS.PROVIDER_REJECTED`、`SMS.PROVIDER_TIMEOUT`、`SMS.RATE_LIMITED`、`SMS.TEMPLATE_NOT_BOUND`、
`SMS.SIGNATURE_NOT_AVAILABLE`、`SMS.NUMBER_INVALID`、`SMS.NUMBER_NOT_SUPPORTED`、`SMS.OPTOUT`、
`SMS.BALANCE_INSUFFICIENT`、`SMS.CAMPAIGN_STATE_INVALID`；全部按 03 §4 注册并补齐 20 种语言文案。

## 安全与合规

- 手机号只存 E.164 + 掩码 + hash；验证码只存 hash，不写日志；发送日志不存正文。
- 频控（Valkey）：单号码 60 秒 1 条、10 分钟 3 条、24 小时 10 条；按场景/全局日配额可配。
- 回执/上行回调：厂商签名校验、时间戳窗口、IP 白名单、按消息 ID 幂等、独立限流。
- 营销短信：使用已审核模板与签名、带退订指引、按接收方时区限制发送时段、退订立即生效。
- 密钥：加密入库、日志脱敏、主密钥仅经环境变量注入；轮换通过 `key_version`。
- 审计：配置、测试发送、重发、群发启停全部记录操作日志。

## 测试

- 单元：变量映射、locale 回退、号码规范化与国家白名单、频控边界、错误码映射、
  加密解密与密钥版本、退订关键词匹配。
- 集成：服务商配置加密读写、日志落库、群发 worker 状态流转与限速、回执幂等更新、上行写入与自动退订。
- 契约：厂商调用使用假 HTTP 服务或 SDK 桩，断言请求签名、超时与重试；**测试不发真实短信**。
- 前端：配置表单、模板绑定、群发导入与进度、日志与退订页面。

## 实施阶段

| 阶段 | 内容 |
|---|---|
| P1 | 服务商（阿里云/腾讯云）、加密配置、签名、模板绑定、单发与验证码、频控、日志、测试发送、独立菜单、`SmsPort` 抽象 |
| P2 | 群发营销（活动、收件人、CSV 导入、去重与退订过滤、worker、进度统计） |
| P3 | 回执轮询与回调、上行接收与自动退订、国际路由与发送时段、成本统计 |

## 风险与备选

- **SDK 依赖体积与升级节奏**：两个厂商 SDK 传递依赖较多，需在 01 锁定版本并纳入依赖审计；
  备选是手写 HTTP 签名（放弃，维护成本高且易随接口变化失效）。
- **群发合规**：营销短信审核、退订、时段由客户运营负责，产品只提供能力与提示。
- **国际覆盖**：一期白名单外的国家直接拒绝，避免在未完成本地合规注册时误发。
- **供应商锁定**：通过 `SmsPort` 抽象与 `provider_code` 解耦，二期可加华为云/火山或通用网关。
- **回执延迟**：轮询存在分钟级延迟，`delivery_status` 允许 `UNKNOWN`，不承诺实时。
