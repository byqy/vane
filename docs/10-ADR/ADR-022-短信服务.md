# ADR-022：短信服务（配置、发送、群发、回执与上行）

| 项 | 值 |
|---|---|
| 状态 | 已接受 |
| 日期 | 2026-10-20 |
| 影响文档 | 01 §2.2、02 §4、03 §18、05 §1 §5.9、07 §10、08 §15、09 §13 |
| 关联 | 沿用 [ADR-009](ADR-009-国际化资源位置.md)「内容入数据库、界面文案入仓库」；与消息模板（`sys_message_template`）共用模板与 i18n 机制 |

## 背景

现有消息能力只有邮件：`sys_message_template` 已支持 `EMAIL / SMS / INAPP` 三种频道，
`MailPort` + `MailDispatcher` 用端口-适配器方式对接 SMTP，SMTP 未配置时降级为日志。
短信缺的是一整条链路：服务商配置、密钥管理、签名、厂商模板映射、发送日志、频控、
群发、送达回执、用户上行（退订）与国际号码支持。

短信与邮件不同：号码与模板必须在服务商侧报备、按国家/地区有独立规则、按条计费、
营销短信有退订与发送时段要求，因此需要独立的配置与管理界面。

## 决策

1. **服务商与 SDK**
   - 一期接入阿里云与腾讯云，使用官方 Java SDK（`com.aliyun:alibabacloud-dysmsapi20170525`、
     `com.tencentcloudapi:tencentcloud-sdk-java-sms`），许可证均为 Apache-2.0；
     具体版本在 P1 实施时锁定并登记 [01 §2.2](../01-技术栈与规范基线.md)。
   - 抽象 `SmsPort`（发送、查询回执、拉取上行）作为业务唯一出口，厂商实现放基础设施层；
     预留 `GenericHttpSmsPort`（可配置 URL/Headers/签名的 HTTP 网关）作为扩展点，一期不实现。
   - 同一 `provider_type` 允许多条配置（如 `aliyun-cn` 与 `aliyun-intl` 两个账号），
     `provider_code` 唯一；`countries` 声明该配置可发送的国家/地区。
   - 每种 `provider_type` 的配置结构由后端校验（见下文「服务商配置结构」）；
     签名只在 `sys_sms_signature` 维护，服务商配置不重复存签名。
2. **配置与密钥**
   - 服务商配置存 `sys_sms_provider.config_cipher`（AES-GCM，随机 nonce，AAD 绑定 `provider_code`）。
   - **密钥环**：`VANE_SMS_SECRET_KEYS` 为 JSON 映射（`{"1":"<base64 key>","2":"<base64 key>"}`），
     `VANE_SMS_SECRET_KEY_ACTIVE` 指定写入使用的版本；读取按 `key_version` 选 key。
   - 缺少 active key 时启动告警并禁止保存服务商配置；历史版本缺 key 时该配置标记为不可用并提示轮换。
   - 轮换流程：新增 key 版本 → 更新 active → 重启 → 后台对每条配置执行「重新加密」（或迁移任务批量重加密）→ 移除旧 key。
   - 查询接口只回显掩码（如 `LTAI****abcd`），写接口不接受回显值回写；日志与错误 detail 不出现密钥。
3. **模板与签名**
   - 站内模板继续用 `sys_message_template`（channel=`SMS`）与 `sys_message_template_i18n`，
     正文支持 `{变量}`；新增 `sys_sms_template_binding` 关联「站内模板 → 服务商模板码 + 签名 + 变量映射」，
     绑定按 `provider_code + country_code + locale` 维度。
   - 发送前校验：绑定存在、必填变量齐全、正文长度符合分段规则；缺失返回
     `SMS.TEMPLATE_NOT_BOUND` / `SMS.TEMPLATE_VARIABLE_MISSING`。
   - 签名在 `sys_sms_signature` 维护（服务商 + 国家 + 语言 + 启停 + 厂商审核状态）。
4. **发送路径与频控**
   - 业务调用 `SmsService.send(scene, phone, locale, variables)`：号码规范化（E.164）→
     按场景频控 → 渲染模板 → 解析绑定 → `SmsPort.send` → 写 `sys_sms_log`（只增）。
   - 频控按场景（系统参数可配）：验证码 60 秒 1 条 / 10 分钟 3 条 / 24 小时 10 条；
     通知类宽松；营销不走单发频控，按活动限速与全局日配额（见决策 5）。
   - 超时：连接 2 秒、读取 5 秒；仅对网络错误与厂商限流做指数退避重试（最多 2 次）。
   - 厂商错误码映射为内部错误码（`SMS.PROVIDER_REJECTED` / `SMS.PROVIDER_TIMEOUT` /
     `SMS.RATE_LIMITED` / `SMS.BALANCE_INSUFFICIENT` 等），按 03 的 Problem Details 返回。
   - 未配置服务商时降级为 `LoggingSmsPort`（记录日志不发送），与邮件未配置 SMTP 一致。
5. **群发营销（几万级）**
   - 不引入 MQ（`docs/01` 范围外），用数据库队列：`sys_sms_campaign` + `sys_sms_recipient`。
   - worker 由定时任务触发，**Valkey 锁**（`SET NX PX` + 续期）保证单实例执行；
     现有 `JobScheduler` 是进程内调度器，无分布式锁，需在本期实现该锁。
   - 每批 200 条、限速可配（默认 100 条/秒）；状态机 `DRAFT → SCHEDULED → RUNNING → PAUSED / DONE / CANCELLED`。
   - 导入：CSV 预校验（`phone`、`params` 列）→ 返回有效/无效/重复/已退订统计与错误行；
     确认后写入收件人；`(campaign_id, phone_e164)` 唯一（部分索引，忽略空值）防止重复导入。
   - 发送前统一过滤 `sys_sms_optout`（`ALL` 与 `MARKETING` 两类都生效）；
     营销模板必须为已审核模板，按接收方时区限制发送时段（默认 8:00–21:00，可配）。
   - 活动级预算与全局日配额：超限拒绝启动或自动暂停，并告警。
6. **回执与上行**
   - **回执独立表 `sys_sms_receipt`（append-only）**：每次状态变化写一行（`log_id`、`status`、
     `provider_status`、`occurred_at`、`raw`），列表与详情取最新一条；`sys_sms_log` 保持只增不改。
   - 回执获取方式按厂商能力区分：
     - 阿里云：查询 API 轮询（`QuerySendDetails`，按手机号 + 日期）；不依赖 MNS。
     - 腾讯云：控制台配置回调优先，拉取接口兜底。
     - 回调端点 `POST /api/v1/public/sms/receipt/{provider}`：厂商签名 + 时间戳窗口 + IP 白名单 + 限流；
       按 `provider_message_id` 幂等。
   - 上行（用户回复）：
     - 腾讯云：回调 + 拉取；
     - 阿里云：需 MNS（消息服务）订阅，**P3 时新增 MNS 依赖并按 ADR/01 登记**；不接 MNS 时，
       阿里云账号的上行能力标记为「不可用」并在界面提示。
     - 统一写 `sys_sms_inbound`；按国家/语言关键词（`TD`、`退订`、`STOP`、`UNSUB` 等）匹配退订，
       命中写入 `sys_sms_optout`（默认范围 `MARKETING`），可配置自动回执确认。
   - 回执（送达状态）与上行（用户回复）是两件事，分别由 `sys_sms_receipt` 与 `sys_sms_inbound` 承载。
7. **国际号码**
   - 号码统一 E.164 存储，解析与规范化用 `com.googlecode.libphonenumber:libphonenumber`（Apache-2.0）。
   - P1 支持范围：中国大陆 + 香港 + 澳门 + 台湾 + 东南亚（SG/MY/TH/VN/ID/PH 等）白名单；
     不在白名单的号码在导入与发送时拒绝（`SMS.NUMBER_NOT_SUPPORTED`）。
   - 按国家/地区路由服务商配置（`countries` + 优先级）；国际短信需服务商国际站账号与独立签名/模板报备。
   - 发送时段按接收方时区（营销）；美国 10DLC、印度 DLT 等注册由客户自行完成，模板不代办，界面提示。
8. **验证码服务**
   - `SmsVerificationService`：生成 6 位数字，Valkey 存 `sms:code:{scene}:{phoneHash}`，TTL 5 分钟；
     校验失败计数 5 次作废；发送冷却 60 秒；只存 hash，不写日志与数据库。
   - 场景枚举：`LOGIN`、`RESET_PASSWORD`、`BIND_PHONE`、`SENSITIVE_OPERATION`；
     接口见 03 §18.3；错误码 `SMS.CODE_EXPIRED` / `SMS.CODE_INVALID` / `SMS.CODE_ATTEMPTS_EXCEEDED`。
9. **管理入口与权限**
   - 独立菜单「运维管理 → 短信服务」，子页：服务商配置、签名、模板绑定、发送日志、群发任务、退订名单。
   - 权限点：`ops:sms`（菜单）、`ops:sms:config`、`ops:sms:template`、`ops:sms:log`、`ops:sms:campaign`、
     `ops:sms:send`、`ops:sms:optout`。
   - 默认授权：`ops:sms:config` 仅 `SUPER_ADMIN`（含密钥）；`ops:sms:template` / `ops:sms:campaign` /
     `ops:sms:send` / `ops:sms:optout` 给 `ADMIN`、`OPERATOR`；`ops:sms:log` 给 `ADMIN`、`OPERATOR`。
   - 配置变更、测试发送、群发启停、手动重发均写审计日志。
10. **数据保留与合规**
    - 手机号只存 E.164 + 掩码 + hash；验证码只存 hash；发送日志不存正文。
    - 保留期（系统参数）：发送日志/回执 180 天、收件人 90 天、上行 180 天；到期由清理任务删除。
    - 支持按号码删除（删除权）：按 `phone_hash` 删除收件人、上行与退订记录（保留已脱敏日志或一并删除，按客户合规要求配置）。

## 服务商配置结构

| `provider_type` | 必需字段 | 可选字段 |
|---|---|---|
| `ALIYUN` | `accessKeyId`、`accessKeySecret`、`regionId` | `endpoint`、`mnsTopic`（P3 上行） |
| `TENCENT` | `secretId`、`secretKey`、`sdkAppId`、`region` | `endpoint`、`callbackToken` |

`countries` 为 ISO-3166 alpha-2 数组（如 `["CN","HK","SG"]`）；同一类型可多条配置，`is_default` 只允许一条。

## 数据模型（迁移 V12）

| 表 | 关键列 | 说明 |
|---|---|---|
| `sys_sms_provider` | `provider_code`(唯一)、`provider_type`、`name`、`config_cipher`、`key_version`、`countries`(jsonb)、`optout_keywords`(jsonb)、`enabled`、`is_default`、审计四列 | 服务商配置 |
| `sys_sms_signature` | `provider_code`、`sign_name`、`country_code`、`locale`、`status`、`provider_approval_status` | 签名 |
| `sys_sms_template_binding` | `template_id` → `sys_message_template`、`provider_code`、`provider_template_code`、`signature_id`、`country_code`、`locale`、`param_mapping`(jsonb) | 模板与变量映射 |
| `sys_sms_log` | `template_code`、`phone_masked`、`phone_hash`、`country_code`、`provider_code`、`provider_message_id`、`campaign_id`、`result`、`error_code`、`duration_ms`、`trace_id`，只增不改 | 发送记录 |
| `sys_sms_receipt` | `log_id`、`provider_message_id`、`status`(`PENDING`/`DELIVERED`/`FAILED`/`UNKNOWN`)、`provider_status`、`occurred_at`、`raw`(jsonb)、`created_at` | 回执（只增） |
| `sys_sms_campaign` | `name`、`template_id`、`provider_code`、`signature_id`、`status`、`scheduled_at`、`throttle_per_second`、`daily_limit`、`budget_amount`、`total`、`sent`、`failed`、审计四列 | 群发活动 |
| `sys_sms_recipient` | `campaign_id`、`phone_e164`、`country_code`、`params`(jsonb)、`source_line`、`status`、`provider_message_id`、`error_code`、`attempts`、`sent_at` | 收件人（含导入错误行） |
| `sys_sms_optout` | `phone_hash`、`scope`(`ALL`/`MARKETING`)、`source`(`MANUAL`/`INBOUND`)、`reason`、`created_at` | 退订与黑名单 |
| `sys_sms_inbound` | `provider_code`、`provider_message_id`、`phone_masked`、`phone_hash`、`content`、`received_at`、`processed`、`matched_keyword` | 上行消息 |

索引：`sys_sms_log(provider_message_id)`、`sys_sms_log(created_at desc)`、
`sys_sms_receipt(log_id, id)`、`sys_sms_recipient(campaign_id, status)`、
唯一部分索引 `uk_sms_recipient_phone (campaign_id, phone_e164) where phone_e164 is not null`、
`sys_sms_optout(phone_hash)`、`sys_sms_inbound(processed, received_at)`。

## 接口契约（03 §18）

后台（`/api/v1/admin/sms/**`，权限点见括号）：

| 方法 | 路径 | 说明 |
|---|---|---|
| GET/POST | `/providers` | 列表 / 新建（`ops:sms:config`） |
| PATCH | `/providers/{code}` | 修改、启停、设默认（`ops:sms:config`）；密钥留空表示不修改 |
| POST | `/providers/{code}/test` | 测试发送（`ops:sms:send`） |
| POST | `/providers/{code}/reencrypt` | 按当前 active key 重新加密（`ops:sms:config`） |
| GET/POST/PATCH | `/signatures` | 签名维护（`ops:sms:config`） |
| GET | `/template-bindings` | 绑定查询（`ops:sms:template`） |
| PUT | `/template-bindings/{templateId}` | 保存绑定（`ops:sms:template`） |
| GET | `/logs` | 日志分页，送达状态取最新回执（`ops:sms:log`） |
| GET | `/logs/export` | CSV 导出（`ops:sms:log`） |
| POST | `/logs/{id}/resend` | 手动重发（`ops:sms:send`） |
| GET/POST/PATCH | `/campaigns` | 群发活动（`ops:sms:campaign`） |
| POST | `/campaigns/import/preview` | CSV 预校验，返回统计与错误行（`ops:sms:campaign`） |
| POST | `/campaigns/{id}/recipients/import` | 确认导入（`ops:sms:campaign`） |
| GET | `/campaigns/{id}/errors` | 错误行导出 CSV（`ops:sms:campaign`） |
| POST | `/campaigns/{id}/start`、`/pause`、`/resume`、`/cancel` | 状态流转（`ops:sms:campaign`） |
| GET | `/campaigns/{id}/recipients` | 收件人分页（`ops:sms:campaign`） |
| GET/POST/DELETE | `/optouts` | 退订名单维护（`ops:sms:optout`） |

公开回调（无用户认证，按签名/IP/限流保护）：

| 方法 | 路径 | 说明 |
|---|---|---|
| POST | `/api/v1/public/sms/receipt/{provider}` | 送达回执 |
| POST | `/api/v1/public/sms/inbound/{provider}` | 上行消息 |

## 错误码

`SMS.PROVIDER_REJECTED`、`SMS.PROVIDER_TIMEOUT`、`SMS.RATE_LIMITED`、`SMS.TEMPLATE_NOT_BOUND`、
`SMS.TEMPLATE_VARIABLE_MISSING`、`SMS.SIGNATURE_NOT_AVAILABLE`、`SMS.NUMBER_INVALID`、
`SMS.NUMBER_NOT_SUPPORTED`、`SMS.BALANCE_INSUFFICIENT`、`SMS.CAMPAIGN_STATE_INVALID`、
`SMS.CAMPAIGN_BUDGET_EXCEEDED`、`SMS.CODE_EXPIRED`、`SMS.CODE_INVALID`、`SMS.CODE_ATTEMPTS_EXCEEDED`；
全部按 03 §4 注册并补齐 20 种语言文案。群发与退订过滤不返回错误，按状态跳过。

## 安全与合规

- 手机号只存 E.164 + 掩码 + hash；验证码只存 hash；日志不存正文。
- 回执/上行回调：厂商签名校验、时间戳窗口、IP 白名单、按消息 ID 幂等、独立限流（Nginx `limit_req` + 应用层）。
- 营销短信：已审核模板与签名、退订指引、按接收方时区限制发送时段、退订立即生效、活动预算与日限额。
- 密钥：加密入库、日志脱敏、主密钥仅经环境变量注入、密钥环轮换。
- 审计：配置、测试发送、重发、群发启停全部记录操作日志。
- 服务商凭证使用最小权限（阿里云 RAM 子账号 / 腾讯云子用户）只授予短信权限。

## 可观测性

- 指标：发送成功率、失败原因分布（按服务商/国家）、发送耗时、回执到达延迟、
  上行数量、活动进度与失败率、余额不足次数。
- 告警：连续失败率超阈值、余额不足、回调验签失败、活动暂停/卡住。

## 测试

- 单元：号码规范化与国家白名单、模板变量映射与缺失校验、locale 回退、频控边界、错误码映射、
  加密解密与密钥环、退订关键词匹配、群发状态机与预算。
- 集成：服务商配置密文读写与掩码回显、重新加密、发送日志落库、回执幂等与状态取最新、
  上行写入与自动退订、群发导入去重与 worker 限速、保留期清理任务。
- 契约：厂商调用使用假 HTTP 服务或 SDK 桩，断言请求签名、超时、重试与错误映射；**禁止发送真实短信**。
- 前端：配置表单（按服务商类型渲染）、模板绑定、导入预览与错误下载、群发进度、日志与退订。

## 实施阶段

| 阶段 | 内容 |
|---|---|
| P1 | 服务商（阿里云/腾讯云）、密钥环加密配置、签名、模板绑定、单发与验证码、场景化频控、日志、测试发送、独立菜单、`SmsPort` 抽象 |
| P2 | 群发营销（活动、导入预校验、去重与退订过滤、worker 与分布式锁、进度统计、预算与日限额） |
| P3 | 回执轮询/回调、上行接收与自动退订（阿里云引入 MNS）、国际路由与发送时段、成本统计、保留期清理 |

## 风险与备选

- **SDK 依赖体积与冲突**：需依赖审计与排除策略；备选手写 HTTP 签名（维护成本高，未选）。
- **阿里云上行依赖 MNS**：若不引入 MNS，阿里云账号无法接收上行；界面需明确标记能力可用性。
- **群发合规**：审核、退订、时段由客户运营负责，产品只提供能力与提示。
- **国际覆盖**：白名单外的国家直接拒绝，避免未完成本地注册时误发。
- **供应商锁定**：通过 `SmsPort` 与 `provider_code` 解耦，后续可加华为云/火山或通用网关。
