# ADR-021：权限点代码化（代码即定义，数据库只存授权）

| 项 | 值 |
|---|---|
| 状态 | 已接受 |
| 日期 | 2026-10-20 |
| 影响文档 | 01 §9、02 §2、03 §12、05 §2、08 §3 §8 |
| 关联 | 沿用 [ADR-008](ADR-008-权限模型.md) 的鉴权模型；与 [ADR-009](ADR-009-国际化资源位置.md) 的「界面文案入仓库」一致 |

## 背景

权限点当前在三个地方各维护一份：Flyway 迁移脚本里的 `INSERT INTO iam_permission`（code + name_key + 类型 + 层级）、接口上的 `@PreAuthorize("hasAuthority('system:user:create')")`、以及 20 种语言的文案。新增一个权限点要同时改三处，容易漏、容易漂移；`name_key` 还没有唯一约束，两个权限点写同一个键会串文案。

同时权限点页直接渲染 `nameKey` 原文（`perm.system.user.create`），43 条 `perm.*` 缺译文，运营看不懂。

权限点在性质上与错误码相同：随功能版本发布、不随运营变化、不允许多处定义。错误码已经采用「枚举 + 文案资源、不落库」的模型，权限点应当一致。

## 决策

1. **唯一定义源：`PermissionCatalog` 枚举**
   - 每项包含 `code`、`type`（`MENU` / `BUTTON`）、`parentCode`、`path`、`component`、`icon`、`sortNo`、`visible`。
   - 新增权限点只改这个枚举；数据库、迁移脚本不再出现权限点数据。
2. **nameKey 由 code 派生，不存储**
   - `MENU` → `menu.` + code 各段（`:` 拆分、`-x` 转驼峰）用 `.` 连接；`BUTTON` → `perm.` + 同样规则。
   - 例：`system:user:reset-password` → `perm.system.user.resetPassword`；`content:article` → `menu.content.article`。
   - 现有 75 条数据 100% 符合该规则，无需改历史文案键。
   - 派生只在后端实现（枚举上一个方法），接口返回 `nameKey` 字段；前端不做二次推导，只 `t(nameKey)`。

1. **唯一定义源：`PermissionCatalog` 枚举**
   - 每项包含 `code`、`type`（`MENU` / `BUTTON`）、`parentCode`、`path`、`component`、`icon`、`sortNo`、`visible`。
   - 新增权限点只改这个枚举；数据库、迁移脚本不再出现权限点数据。
2. **nameKey 由 code 派生，不存储**
   - `MENU` → `menu.` + code 各段（`:` 拆分、`-x` 转驼峰）用 `.` 连接；`BUTTON` → `perm.` + 同样规则。
   - 例：`system:user:reset-password` → `perm.system.user.resetPassword`；`content:article` → `menu.content.article`。
   - 现有 75 条数据 100% 符合该规则，无需改历史文案键。
   - 派生只在后端实现（枚举上一个方法），接口返回 `nameKey` 字段；前端不做二次推导，只 `t(nameKey)`。
   （根菜单只有一段），由测试强制。
3. **数据库只保存授权关系**
   - `iam_role_permission` 改为 `(role_id, permission_code)`，删除 `permission_id` 与 `iam_permission` 表。
   - 授权关系仍入库并留痕（审计要求），权限定义不入库。
   - 角色授权的读写在应用层用 `PermissionCatalog.exists(code)` 校验，拒绝未知 code。
4. **鉴权仍走 `hasAuthority`，注解引用枚举常量**
   - `BearerAuthenticationFilter` 的 authorities 来自 `iam_role_permission.permission_code`，不再与权限表 join。
   - `@PreAuthorize` 改为 SpEL 引用常量：`hasAuthority(T(xyz.byqy.vane.iam.domain.PermissionCatalog).SYSTEM_USER_CREATE.code)`，拼错即编译失败。
5. **菜单由枚举生成**
   - `/auth/me` 的 `menus` 从「用户已授权的 MENU 型 code 集合」过滤枚举生成，字段（path / component / icon / sortNo / nameKey）与现在一致。
6. **授权树由枚举生成**
   - `GET /admin/permissions/tree` 直接构造树，节点 `id` 使用 `code`；`PUT /admin/roles/{id}/permissions` 的请求体改为 `{ "permissionCodes": [...] }`，响应改为 code 数组。
7. **文案边界**
   - 权限名属于界面文案：前端 `locales/<locale>.ts` 维护派生出的 `menu.*` / `perm.*` 键，界面 `t(nameKey)`。
   - 错误码与校验消息仍由后端 `MessageResolver` 解析。
   - 预留：接口可增加 `displayName`（服务端按 `Accept-Language` 解析），供未来 App / 开放 API / 邮件使用，本期不实现。
8. **清理策略**
   - 迁移时删除指向不存在权限的授权行；运行期不写库、不做启动同步，未知 code 的残留授权在鉴权时自然不生效。
   - 权限点删除 = 从枚举移除 + 新迁移清理对应授权行（可选）。

## 数据库迁移（V11）

```sql
-- 1) 授权关系改按权限码引用
ALTER TABLE iam_role_permission ADD COLUMN permission_code text;
UPDATE iam_role_permission rp
   SET permission_code = p.code
  FROM iam_permission p
 WHERE p.id = rp.permission_id;
DELETE FROM iam_role_permission WHERE permission_code IS NULL;
ALTER TABLE iam_role_permission ALTER COLUMN permission_code SET NOT NULL;
ALTER TABLE iam_role_permission DROP CONSTRAINT iam_role_permission_pkey;
ALTER TABLE iam_role_permission DROP CONSTRAINT iam_role_permission_permission_id_fkey;
ALTER TABLE iam_role_permission DROP COLUMN permission_id;
ALTER TABLE iam_role_permission ADD PRIMARY KEY (role_id, permission_code);
CREATE INDEX idx_iam_role_permission_code ON iam_role_permission (permission_code);
-- 2) 权限定义不再入库
DROP TABLE iam_permission;
```

历史迁移 V2 / V5 / V6 / V7 / V10 中创建与插入权限点的语句保持不变（已执行脚本不得修改）；全新库按序执行后由 V11 收敛。

## 风险

- **code 不可变**：code 同时是鉴权标识和文案键来源，发布后改名会同时破坏授权记录与译文，必须按「新增 code + 迁移授权 + 删除旧 code」处理。
- **枚举与授权数据漂移**：枚举删掉的 code 会留下孤儿授权行；靠迁移清理与「未知 code 不生效」兜底，不做启动同步。
- **破坏性迁移**：`iam_permission` 直接删除；模板项目尚无外部客户数据，可一次完成；已有部署需先备份。
- **翻译漏配**：派生键漏翻译会显示原始 key（可接受的降级），由 20 语言门禁测试拦截。
- **注解可读性**：SpEL 表达式变长，靠统一格式与代码评审维持可读性；不引入自定义注解以规避授权链路的额外风险。

## 备选方案与未选原因

| 方案 | 做法 | 未选原因 |
|---|---|---|
| A 启动同步 | 枚举 + 启动时 upsert 到 `iam_permission` | 仍需权限表与同步器，多实例并发与审计复杂度高，未解决「定义入两份」 |
| B 生成迁移 | 枚举生成 `V{n}__permissions.sql` | DB 仍存定义副本，新增权限点还要跑生成器与提交迁移 |
| C 只补文案 | 保留现状，补 43 条译文 | 三处维护的问题仍在 |
