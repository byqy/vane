# ADR-029：前端测试工具链主版本升级（Vitest 5、@types/node 26）

| 项 | 值 |
|---|---|
| 状态 | 已接受 |
| 日期 | 2026-10-28 |
| 影响文档 | `docs/01-技术栈与规范基线.md`、`docs/需求设计总纲.md` §3、`CHANGELOG.md` |
| 关联 | [ADR-028](ADR-028-依赖版本基线批量升级.md)（同批依赖升级中补丁/次版本部分）；[ADR-016](ADR-016-前端按需引入与自动导入.md) |

## 背景

ADR-028 完成了补丁与次版本层级的依赖升级，主版本升级留待逐项评估。Dependabot 随后就前端测试工具链提出两个主版本升级：

| 依赖 | 原版本 | 目标版本 | 性质 |
|---|---|---|---|
| `vitest` | 3.2.7 | 5.0.5 | 测试运行器主版本，配置与内部 API 可能不兼容 |
| `@types/node` | 24.19.2 | 26.6.5 | 类型定义主版本，须与 Node 26 运行时匹配 |

`@types/node` 的目标版本与本项目 Node **26** 基线（01 §2.1）本应一致，长期停留在 24 属于基线漂移；`vitest` 升主版本则直接影响 248 个前端测试能否运行。

## 决策

1. **两项一并接受**：二者同属前端测试工具链，`vitest` 5 与 `@types/node` 26 在同一次评估中验证，避免出现「新运行器 + 旧类型」的中间态。
2. **验收标准是全量前端门禁通过**：`pnpm -r typecheck`、`pnpm -r test`、`pnpm -r build` 三项全绿，测试数量不得减少（基线 shared 40 + portal 53 + admin 155 = 248）。若 `vitest` 5 出现无法在不放宽断言的前提下解决的问题，则退回 `vitest` 3 并在 `dependabot.yml` 中忽略其主版本。
3. **类型定义跟随运行时**：Node 26 为唯一受支持运行时，`@types/node` 与之保持同主版本，避免类型与运行时的偏差。
4. **`vitest` 5 不引入新配置**：沿用现有 `vitest run` 与 jsdom 环境配置；若升级要求改写配置，须先评估对 248 个用例的影响面。

## 影响

| 项 | 影响 |
|---|---|
| 依赖基线 | `docs/01` §2.2 的 Vitest 版本更新为 5.0.5，并登记 `@types/node` 26.6.5 |
| 测试 | 用例数与断言不变，248 个前端测试在 `vitest` 5 下全部通过 |
| 构建 | `typecheck` 与 `build` 均通过，无配置改写 |
| 流程 | 主版本升级仍由 Dependabot 单独提出 PR，逐项评估后合入（ADR-028 决策 9） |

## 风险与取舍

- **`vitest` 主版本的行为差异**：5.x 对快照、覆盖率 provider、浏览器模式有调整；本项目不依赖快照与浏览器模式，风险限于执行器与报告格式变化，已由全量用例覆盖验证。
- **类型定义主版本带来的编译错误**：`@types/node` 26 可能收紧部分 Node API 的类型；`tsc --noEmit` 已验证无新增错误。
- **依赖树变动**：主版本升级会牵动 `vite`、`@vitest/*`、`jsdom` 等传递依赖，可能引入未来补丁升级的兼容问题；由 ADR-028 的分组规则与常规门禁持续观察。
