# ADR-028：依赖版本基线批量升级（Dependabot 首批 12 项）

| 项 | 值 |
|---|---|
| 状态 | 已接受 |
| 日期 | 2026-10-28 |
| 影响文档 | `docs/01-技术栈与规范基线.md`、`docs/需求设计总纲.md` §3、`vane-web/AGENTS.md`、`CHANGELOG.md`、`.github/workflows/ci.yml` |
| 关联 | [ADR-016](ADR-016-前端按需引入与自动导入.md)（unplugin 用法）、[ADR-022](ADR-022-短信服务P1基础.md)（libphonenumber 用途） |

## 背景

仓库开源（ADR-026、ADR-027）后，GitHub 侧 Dependabot 在首次运行即产出 12 个升级 PR。基线规则要求「不得擅自升降依赖版本，调整需要 ADR」（总纲硬性规则 6），因此这批升级不能直接合入，必须由 ADR 统一授权并同步 `docs/01` 的版本基线。

12 项分为三类：

- **补丁级**：JaCoCo 0.8.14→0.8.15、Spring Boot 4.1.1→4.1.2、Vite 8.3.4→8.3.5、vue-i18n 11.4.14→11.4.16。
- **主版本级**：libphonenumber 8.13.43→9.0.42、jsdom 27→30、unplugin-vue-components 28→32、unplugin-auto-import 19→21。
- **CI 动作主版本级**：actions/checkout 4→7、actions/setup-java 4→6、actions/setup-node 4→7、pnpm/action-setup 4→6。

## 决策

1. **整批接受**，理由是每一项都不改变对外契约：补丁级无行为差异；主版本级集中在号码解析（libphonenumber）、测试 DOM 环境（jsdom）与构建期插件（unplugin），均不进入运行时对外接口；CI 动作只影响流水线自身。
2. **libphonenumber 升到 9.x 是本次唯一需要确认的破坏性变更**：其 `PhoneNumberUtil` 系列 API 在 9.x 有签名调整，须由既有号码解析用例（ADR-022 相关测试）验证 E.164 规范化与解析结果不变。
3. **unplugin 两个插件只承担构建期解析**（`el-*` 按需引入、resolver 自动导入），升级后必须以 `apps/admin` 构建产物与组件测试验证「按需引入仍然生效」，不能只看构建不报错。
4. **jsdom 30 仅影响 Vitest 的 DOM 环境**，升级后要求 `packages/shared`、`apps/admin`、`apps/portal` 三套测试全部通过。
5. **CI 动作按主版本升级**，并在升级前用 GitHub API 确认目标 tag 存在（`v7`/`v6`/`v7`/`v6`），避免流水线引用不存在的版本。
6. **锁文件由 pnpm 重新生成**而非手工合并：多个 Dependabot 分支同时改写 `pnpm-lock.yaml`，冲突解决后统一 `pnpm install --fix-lockfile` 重建，保证锁文件自洽。
7. **Maven 分发地址改用 Maven 中央仓库**：`vane-server/.mvn/wrapper/maven-wrapper.properties` 原指向 `maven.aliyun.com` 镜像，该地址在境外 runner 上不可达，导致 GitHub Actions 的后端 job 自首次运行起即失败（前端 job 不受影响）。改为中央仓库标准地址 `repo.maven.apache.org`，使 CI 结果只反映代码状态，不受镜像可达性影响。
8. **服务端默认语言固定为 `zh-CN`**：此前未配置默认请求语言，Spring 回落到 JVM 默认 locale，同一份部署在中文 Windows 与英文 runner 上返回不同语言的错误文案，集成测试在 CI 上批量失败。改为在 `application.yaml` 显式声明 `spring.web.locale: zh_CN`（与 04 §1 的默认语言约定一致），请求带 `Accept-Language` 时仍按请求头协商。
9. **Dependabot 按升级类型分组**：补丁与次版本升级合并为单个 PR，主版本升级保持单独 PR，避免每周产生十余个零散 PR 淹没评审。

## 影响

| 项 | 影响 |
|---|---|
| 依赖基线 | `docs/01` §2.1 / §2.2 与附录 B 的版本号同步更新，本文为该次调整的唯一授权依据 |
| 后端 | Spring Boot 4.1.2（补丁）、JaCoCo 0.8.15（覆盖率工具）、libphonenumber 9.0.42（号码解析） |
| 前端 | Vite 8.3.5、vue-i18n 11.4.16、jsdom 30.1.3、unplugin-vue-components 32.1.0、unplugin-auto-import 21.1.0 |
| CI | `actions/checkout@v7`、`actions/setup-java@v6`、`actions/setup-node@v7`、`pnpm/action-setup@v6` |
| 验证 | 后端 `mvnw test` 全绿（含 46 个集成测试）；前端 `pnpm -r typecheck / test / build` 全绿（248 个测试） |
| 流程 | Dependabot PR 通过合入其分支关闭，保持 PR 记录与版本基线变更一一对应 |
| 构建 | Maven wrapper 的分发地址改为中央仓库，消除 CI 对地域镜像的依赖 |

| 协作 | Dependabot 补丁/次版本升级合并为单个 PR，降低评审噪音 |

## 风险与取舍

- **补丁级升级的隐性回归**：Spring Boot 4.1.2 属于框架补丁版本，可能影响自动配置装配；由全量后端测试 + 覆盖率门禁兜底。
- **主版本的隐性语义变化**：jsdom 30 可能改变部分 DOM API 行为（例如 `structuredClone`、`CSS` 对象实现），前端测试全绿是唯一判据；若后续出现偶发失败，优先回退到 jsdom 27。
- **CI 动作主版本**：checkout v7 等动作要求更新的 runner 运行时；若 GitHub-hosted `ubuntu-latest` 尚未提供，将以流水线失败暴露，届时按需回退到上一主版本并另立记录。
- **不做分批灰度**：本仓库为模板项目、依赖面窄，整批升级的验证成本低于长期维护 12 个分散分支的成本。
