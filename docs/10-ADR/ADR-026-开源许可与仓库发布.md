# ADR-026：开源许可与仓库发布

| 项 | 值 |
|---|---|
| 状态 | 已接受 |
| 日期 | 2026-10-27 |
| 影响文档 | 01 §3、`README.md`、`docs/README.md` |
| 关联 | 与 [ADR-001](ADR-001-项目代号.md)（代号 vane）一致；不修改任何既有 ADR 的结论 |

## 背景

项目已具备可复制交付的完整实现（后端 9 模块、前端三包、50 张表、20 语言、11 份设计分册），准备公开到代码托管平台，供同类机构直接复用。公开发布涉及三件事：**用户使用本项目时的法律许可**、**托管平台的选择与主从关系**、**发布前必须清理的仓库内容**。

## 决策

1. **许可证采用 MIT**
   - 项目定位是「可整体复制到新机构使用的模板」，MIT 的约束最少（保留版权与许可声明即可），符合「越宽越好」的诉求。
   - 不采用 Apache-2.0：其专利授权条款对本项目（无专利主张的模板工程）收益有限，反而增加 NOTICE 维护与合规解释成本。
   - 依赖许可证仍按 01 §3 的三色名单治理（白名单/黑名单/灰名单），与项目自身许可解耦。

2. **主仓库为 Gitee，GitHub 为只读镜像**
   - Issue 与 Pull Request 统一在 Gitee 受理；GitHub 侧在 `README.md` 顶部与 Issue 模板中明确说明，避免双平台分裂。
   - GitHub 镜像由主仓推送（本地 `git push github` 或 Gitee Go 流水线），因为 **GitHub 没有原生「从 Gitee 拉取」的镜像能力**；Gitee 自带的仓库镜像只支持「从 GitHub 拉取到 Gitee」方向。
   - CI 使用 GitHub Actions（在镜像仓运行）；Gitee 侧不配置等价流水线，提交前以本地门禁为准。

3. **发布前仓库清理（公开即不可逆，必须先做）**
   - 移出版本库的历史临时产物：`vane-web/.locale-data/`、根目录 `.tmp-*` 脚本；`.gitignore` 补充 `.locale-data/`、`data/`、`*.pid`。
   - 补齐开源必备文件：`LICENSE`、`README.md`（特性/架构/快速开始/文档索引/质量门禁/版本说明）、`CONTRIBUTING.md`、`SECURITY.md`、`CODE_OF_CONDUCT.md`、`CHANGELOG.md`、`.editorconfig`、`.github/`（CI、Issue/PR 模板、Dependabot）。
   - 全历史密钥扫描：确认无真实密钥、私钥、个人绝对路径与内网地址；示例口令（如本地开发库 `admin / Admin@12345`）必须在文档中标注「仅本地示例」。
   - `vane-server/mvnw` 标记为可执行（`100755`），保证 Linux CI 可直接运行。

4. **版本与兼容承诺**
   - 首发标签 `v0.1.0`；0.x 阶段明确「接口、表结构、内部模块可能变动」，README 与 `CHANGELOG.md` 均载明，避免使用者按 1.0 语义依赖。

## 影响

| 项 | 影响 |
|---|---|
| 仓库 | 新增 `LICENSE`、社区文件与 CI；删除历史临时产物；`.gitignore` 扩充 |
| 文档 | `README.md` 重写（面向外部使用者）；`docs/README.md`、总纲 §3 同步 ADR 数量；01 §3 补充项目自身许可 |
| 流程 | 贡献入口收敛到 Gitee；本地门禁成为主仓的强制前置 |
| 风险 | GitHub 镜像依赖主动推送，可能出现滞后；已在 README 标注「镜像只读、以 Gitee 为准」 |

## 风险与取舍

- **双平台分裂**：GitHub 有更好的发现性，但贡献必须回到 Gitee；若未来 GitHub 成为主要流量入口，需重新评估主从关系（另行 ADR）。
- **镜像滞后**：推送式镜像不是实时的；Gitee Go 或本地脚本失败时 GitHub 会落后，README 已声明以 Gitee 为准。
- **示例凭据**：模板需要开箱可跑，示例账号与默认口令保留在文档中，但明确标注不可用于真实环境，并在 `SECURITY.md` 的部署须知中重申。
