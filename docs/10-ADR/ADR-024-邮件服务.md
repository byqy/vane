# ADR-024：邮件服务（SMTP）

| 项 | 值 |
|---|---|
| 状态 | 已接受 |
| 日期 | 2026-10-21 |
| 影响文档 | 02 §4、03 §20、05 §5.10 §9、06 §5 §6、07 §3 §10、08 §17、09 §15 |
| 关联 | 复用 [ADR-022](ADR-022-短信服务.md) 的密钥环与数据库队列模式；沿用 [ADR-023](ADR-023-审计日志精细化.md) 的 L2 变更记录 |

## 背景

消息通知目前只有「模板」与「发送器」两块：

- `sys_message_template` 存 code + channel（EMAIL/SMS/INAPP）+ 多语言主题/正文，后台「消息模板」页可编辑与发测试；
- `MailDispatcher` 直接读 `spring.mail.host`，有 SMTP 就走、没有就把邮件写成一条日志；
- 权限点只有 `ops:mail`（菜单）与 `ops:mail:send`（发送测试）。

缺的是「服务」这一层：没有 SMTP 配置界面（只能改 YAML/环境变量），没有密钥加密入库，
没有发送日志（发没发出去、为什么失败都查不到），没有异步与重试，没有限额与保留期。
短信服务（ADR-022）已经把这套骨架跑通，邮件按同样的模式补齐即可，但范围收敛到 SMTP。

## 决策

### 1. 范围

| 项 | 本期 |
|---|---|
| 服务商 | **仅 SMTP**（host/port/TLS/用户名/密码/发件人） |
| 发送 | 模板渲染 → 入队 → worker 异步发送 → 重试 |
| 日志 | 每次发送一行 `sys_mail_log`，含状态、错误、耗时、traceId |
| 测试 | 服务商连通性校验 + 模板测试发送 |
| 页面 | 邮件页改为三页签：模板 / 服务商 / 发送日志 |
| 非本期 | 第三方邮件 API（SES、阿里云邮件推送）、HTML 正文、附件、退信/投诉处理、多服务商路由与成本统计（P2） |

### 2. 密钥与配置

- 泛化现有 AES-GCM 密钥环为 `SecretCipher`：`encrypt(aad, plaintext)` / `decrypt(aad, ciphertext)`，
  AAD 区分用途与归属（短信 `sys_sms_provider:<code>`、邮件 `sys_mail_provider:<code>`、
  收件人 `sys_mail_log:<id>`）。
- 环境变量统一为 `VANE_SECRET_KEYS`（版本 → base64 32 字节密钥）与 `VANE_SECRET_KEY_ACTIVE`；
  旧 `VANE_SMS_SECRET_KEYS` / `VANE_SMS_SECRET_KEY_ACTIVE` 作为兼容回退，二者择一。
- SMTP 密码**只写不读**：接口返回恒为 `***`；`PATCH` 时密码为空表示保持原值。
- 密钥版本随密文入库（`key_version`），支持多版本并行解密与滚动重加密。
- 收件人检索用 `to_hash = HMAC-SHA256(active key, 小写地址)`，只用于精确匹配，不可逆。

### 3. 数据模型（迁移 V17）

`sys_mail_provider`：

| 列 | 类型 | 说明 |
|---|---|---|
| `id` | uuid PK | |
| `code` | text 唯一 | 服务商标识 |
| `name` | text | 显示名 |
| `host` / `port` | text / int | SMTP 地址与端口（1–65535） |
| `tls_mode` | text CHECK | `NONE` / `STARTTLS` / `SSL`，默认 `STARTTLS` |
| `username` | text | 认证用户名，可空（匿名中继） |
| `password_cipher` | text | AES-GCM 密文，可空 |
| `key_version` | text | 密文密钥版本 |
| `from_address` / `from_name` | citext / text | 发件人 |
| `enabled` / `is_default` | boolean | 启用与默认 |
| `daily_limit` | int | 日发送上限，默认 500 |
| `timeout_ms` | int | 连接/发送超时，默认 10000 |
| 审计四列 | | `created_at/by`、`updated_at/by` |

约束：`uk_sys_mail_provider_default (is_default) where is_default` 保证唯一默认；首个服务商自动成为默认；
删除或禁用默认服务商返回 409 `MAIL.PROVIDER.IN_USE`；切换默认在同一事务内取消原默认。

`sys_mail_log`（业务表，可清理）：

| 列 | 类型 | 说明 |
|---|---|---|
| `id` | uuid PK | uuidv7 |
| `provider_code` | text | 发送使用的服务商（logging 模式为 `logging`） |
| `template_code` / `locale` | text | 渲染来源 |
| `to_masked` / `to_domain` | text | 收件人掩码与域名（展示与域筛选） |
| `to_cipher` / `to_key_version` | text | 收件人密文，worker 重试时解密使用 |
| `to_hash` | text | HMAC，供精确筛选 |
| `variables` | jsonb | 渲染变量；**终态（SENT/FAILED）置空**，只在排队期保留 |
| `subject` | text | 终态保留渲染主题（不存正文） |
| `status` | text CHECK | `QUEUED` / `SENT` / `FAILED` |
| `error_code` / `error_detail` | text | 失败原因（不含凭据与正文） |
| `attempts` | int | 已尝试次数 |
| `next_attempt_at` | timestamptz | 下次重试时间 |
| `duration_ms` / `trace_id` | int / text | |
| `created_at` / `sent_at` | timestamptz | |

索引：`(created_at desc)`、`(status, next_attempt_at)`、`(template_code, created_at desc)`、
`(provider_code, created_at desc)`、`(to_hash, created_at desc)`。`provider_code` 不建外键，
删除服务商后历史日志仍可读。

同时登记任务：`mail-send-worker`（30 秒）、`mail-log-retention`（每日 03:40），
并给 `SUPER_ADMIN` / `ADMIN` 授予新增权限点。

### 4. 发送链路

1. `POST /admin/mail/send`（以及模板页测试发送）：校验收件人与模板 → 渲染 → 检查服务商与当日限额 →
   同一事务写 `sys_mail_log`（`QUEUED`，含 `to_cipher`、`to_hash`、`variables`）→
   返回 202 + `logId`（附带渲染后的主题/正文供预览）。
2. `mail-send-worker`：Valkey 锁 `vane:mail:send:lock`（TTL 60 秒，任务 30 秒一轮），
   每轮取 50 条 `status='QUEUED' AND (next_attempt_at IS NULL OR next_attempt_at <= now())`；
   单条独立事务更新状态，不在事务内做远程调用。
3. 失败分类：
   - 可重试（连接失败、超时、SMTP 5xx）：`attempts < 3` 时置 `QUEUED`，退避 1 / 5 / 15 分钟；
   - 不可重试（认证失败、收件人拒绝、模板变量缺失）：立即 `FAILED`。
4. 终态（`SENT` / `FAILED`）写入 `sent_at`、`error_code`、`subject`，并把 `variables` 置空。
5. 投递语义为**至少一次**：worker 在「发送成功、更新状态前」崩溃可能重发一封，邮件无法幂等，
   记录接受该权衡并写入运维说明。
6. 模式 `vane.mail.mode`：
   - `smtp`（默认）：走真实 SMTP；
   - `logging`（本地/演示显式开启）：不联网，直接置 `SENT`，`provider_code=logging`。
   `smtp` 模式下无启用服务商时，发送请求返回 409 `MAIL.NOT_CONFIGURED`。

### 5. 限额与保留

- 每个服务商 `daily_limit` 默认 500；按 **UTC 当日** 统计 `SENT` 行数，超限返回 429 `MAIL.QUOTA.EXCEEDED`。
  并发入队可能短暂超过限额（近似限额），不做分布式计数。
- `sys_mail_log` 默认保留 180 天，`mail-log-retention` 每日 03:40 删除过期行
  （应用账号可删自己的业务表，与审计表的外部清理不同）。

### 6. 审计

- 服务商 create/update/delete 走 L2：记录 `host/port/tlsMode/fromAddress/enabled/isDefault/dailyLimit`
  的前后值，**密码恒 `***`**。
- 发送动作 L1：`module=mail`、`action=send`、`targetType=mail-log`、`targetId=logId`、
  `affectedCount=1`。
- 测试发送同样写审计。

### 7. 与现有代码的衔接

- `MailPort` 改为按服务商发送：`MailPort.send(MailProvider provider, MailMessage message)`；
  `MailDispatcher` 用 `JavaMailSenderImpl` 按 provider 构建并缓存，替换对 `spring.mail.*` 单例的依赖；
  `spring.mail.*` 标记为废弃配置，不再读取。
- 模板页现有 `POST /admin/message-templates/{code}/send` 改为调用邮件服务入队，成功返回 **202**；
  不再同步直发，也不再返回 200。
- `GET /admin/message-templates` 的权限放宽为 `hasAnyAuthority(ops:mail, ops:sms)`：
  短信页绑定模板需要读列表，原实现只认 `ops:mail`，短信运营角色会被 403。

## 备选（未选）

| 备选 | 不选原因 |
|---|---|
| 继续只用 YAML 配置 | 运维不可自助，密码只能放环境变量且无法轮换 |
| 请求内同步发送 | 阻塞请求、违反 01 §262「事务内不做远程调用」；失败即丢 |
| 只接第三方 API（SES/阿里云） | 需要额外依赖与国内合规评估，先以 SMTP 覆盖自建/企业邮箱 |
| 引入消息队列中间件 | 与 01 §2.3 范围外技术冲突；数据库队列足够本量级 |
| 存完整收件人明文 | PII 风险；改为密文 + HMAC + 掩码 |
| HTML 正文与附件 | 先保证纯文本可送达，富文本与附件另立 ADR |

## 后果

- 正向：邮件从「改配置才能发」变成可自助配置、可追溯、失败可重试；密钥不再以明文躺在环境变量里。
- 成本：多两张表、一个 worker 任务与一个清理任务；发送改为异步后，前端需要按 `logId` 查询状态。
- 约束：仅纯文本、仅 SMTP；至少一次投递；多服务商/退信/统计留待 P2。

## 测试

- 单元：密钥环加解密与 AAD 隔离、`to_hash` 稳定性、服务商参数校验（端口/TLS/发件人）、
  收件人校验、主题换行过滤、可重试/不可重试分类、退避计算、限额判断、掩码。
- 集成：服务商 CRUD（密码不回显、唯一默认、删除默认 409）、连通性校验（logging 模式成功）、
  发送入队 → worker → `SENT`（`variables` 已清空）、不可重试错误 → 立即 `FAILED`、
  可重试错误 → 重试后 `FAILED`、限额 429、权限点 403、审计 L2 无密码、日志保留任务、
  短信运营可读模板列表。
- 前端：三页签渲染与权限隐藏、服务商表单、日志筛选、测试发送对话框（202 后查状态）。
- 契约：202 + `logId`、404/409/422/429 状态码、导出 CSV 列、列表不含完整收件人。

## 实施顺序

1. V17 迁移、实体与仓库；
2. `SecretCipher` 泛化与短信兼容；
3. 服务商 CRUD + 连通性校验 + 唯一默认规则；
4. 发送入队、worker、重试分类与限额；
5. 日志查询/导出、模板列表权限放宽与审计接入；
6. 前端三页签；
7. 错误码 20 语言、测试与覆盖率。
