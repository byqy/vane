### 2.4 Spring Boot 4 的模块化差异

Spring Boot 4 起，自动配置按功能拆分为独立模块，starter 名称与传递依赖随之变化。**只添加底层库不会再触发自动装配**，且失败是静默的（应用正常启动、功能不生效）。落地时须注意：

| 场景 | 错误做法 | 正确做法 |
|---|---|---|
| 数据库迁移 | 只加 `org.flywaydb:flyway-core`（应用能启动，迁移不执行） | 加 `org.springframework.boot:spring-boot-starter-flyway` |
| JSON 序列化 | 期望 `spring-boot-starter-web` 自带 Jackson | 显式加 `spring-boot-starter-jackson` |
| 参数校验 | 期望 Web starter 自带 Validation | 显式加 `spring-boot-starter-validation` |

另有两处包名变更：

- Jackson 升级到 **3.x**，主包名为 `tools.jackson.*`；`com.fasterxml.jackson.*` 仅保留注解等兼容部分。
- 校验与 Jackson 的 starter 名称以本文 §2.1 为准，不得凭旧版经验推断。
- `vue-tsc` 尚不兼容 TypeScript 7（找不到 `typescript/lib/tsc` 导出），前端类型检查使用 `tsc --noEmit`；模板级类型检查待 vue-tsc 支持 TS 7 后恢复。

## 4. 工程结构与模块边界

### 4.1 后端（Maven 多模块）

```text
vane-server/
├─ vane-common/          # HTTP 语义、Problem Details、错误码注册表、i18n 工具、审计切面、通用异常
├─ vane-iam/             # 用户、角色、权限点、组织、数据范围、会话、令牌
├─ vane-system/          # 系统参数、字典、编号规则、定时任务
├─ vane-content/         # 公告、内容页、导航
├─ vane-file/            # 附件与存储抽象
├─ vane-audit/           # 操作日志、登录日志、审计查询
├─ vane-api-admin/       # 后台管理 API（controller + DTO）
├─ vane-api-portal/      # 前台门户 API（controller + DTO）
└─ vane-bootstrap/       # 启动装配、Flyway 迁移、配置
```

**分层（每个业务模块内部）**：`api → application → domain → infrastructure`。

### 4.2 前端（pnpm workspace）

```text
vane-web/
├─ packages/shared/     # 设计令牌、请求封装、i18n 公共资源、OpenAPI 生成类型
├─ apps/admin/          # 后台管理端
└─ apps/portal/         # 前台门户端
```

**部署映射（Nginx）**：

| 路径 | 产物 | fallback |
|---|---|---|
| `/` | `apps/portal` | `try_files $uri $uri/ /index.html` |
| `/admin/` | `apps/admin`（Vite `base=/admin/`） | `try_files $uri $uri/ /admin/index.html` |
| `/api/` | 后端应用 | 反向代理 |

### 4.3 依赖方向规则（必须可被架构测试验证）

1. `vane-common` **不得**依赖任何业务模块。
2. `api-*` 模块 **不得**被其他模块依赖（它是最外层）。
3. Controller **不得**直接依赖 Repository 或实体；只能依赖 application 层用例。
4. DTO 与实体 **必须**分离，转换用 MapStruct。
5. 数据库访问 **只允许**出现在 `infrastructure` 层。
6. 跨模块调用 **只能**经 application 层公开接口，禁止直接引用对方 repository/实体。

> 用 ArchUnit 落成测试，规则不通过则构建失败。

### 4.4 命名

- 项目代号 **`vane`**（风向标：感知变化、随风转向）。
- Maven `groupId`：`xyz.byqy`；`artifactId`：`vane-<module>`。
- 基础包：`xyz.byqy.vane.<module>.<layer>`，全小写，禁止下划线。
- 类：`UpperCamelCase`；方法/变量：`lowerCamelCase`；常量：`UPPER_SNAKE_CASE`。
- 接口不带 `I` 前缀；实现类用 `Default`/具体语义后缀，不用 `Impl` 除非无更优命名。

### 4.5 配置与密钥

| 项 | 约定 |
|---|---|
| 配置来源 | 环境变量 > `application-<profile>.yaml` > `application.yaml`；禁止把环境相关值写死在代码里 |
| 密钥 | 只经环境变量或密钥管理服务注入；**不得**入库、不得进前端产物、不得出现在日志 |
| 敏感配置 | 需脱敏展示；导出配置时排除 |
| 默认值 | 允许有安全默认值；危险能力（调试端点、演示模式）默认关闭 |

## 5. Java 编码规范

### 5.1 语言特性

- 语言级别 **25**，`--release 25`。
- **应当**使用 `record` 表达不可变 DTO/值对象。
- **可以**使用密封类、模式匹配、文本块。
- **谨慎**使用虚拟线程：I/O 密集场景可用，须配合现有连接池限制，禁止无脑全量切换。
- **不得**使用 `java.util.Date` / `Calendar`；统一 `java.time`。

### 5.2 空值与集合

- Repository 返回 `Optional<T>`；Service **不得**把 `Optional` 当字段或方法参数。
- **不得**返回 `null` 集合；空集合返回 `List.of()`。
- **不得**返回 `null` 字符串；用空串或明确语义。

### 5.3 异常

- 业务失败抛 `BusinessException(code)`；`httpStatus` 与 `type` 由 [03 §4](03-HTTP语义与错误模型规范.md) 的错误码注册表解析，业务代码不直接指定状态码。
- 由 `@RestControllerAdvice` 统一转为 Problem Details。
- **不得**捕获 `Throwable`、`Exception` 后吞掉；捕获必须记录并重新抛出或明确降级。
- **不得**用异常做流程控制（除校验短路）。
- 对外**不得**暴露堆栈、SQL、内部类名。

### 5.4 日志

- 使用 SLF4J 参数化：`log.info("user {} created", id)`，禁止字符串拼接与 `+` 拼日志。
- **不得**记录密码、令牌、身份证、手机号等敏感字段（必要时脱敏）。
- 每条请求日志带 `traceId`；错误日志带 `code` 与 `traceId`。
- 结构化日志字段：`timestamp`、`level`、`logger`、`traceId`、`userId`、`method`、`path`、`status`、`durationMs`、`code`、`message`。
- 敏感字段（密码、令牌、身份证、手机号、邮箱）在序列化前脱敏。

### 5.5 事务与并发

- `@Transactional` **只允许**出现在 application 层的用例方法上；查询标 `readOnly = true`。
- **不得**在事务内做远程调用、发送邮件、写文件。
- 并发更新一律依赖显式 `@Version` 乐观锁，**不得**用「先查后改」裸写。

### 5.6 Lombok 使用边界

- **可以**：`@Getter`、`@Setter`（仅 DTO）、`@Builder`、`@RequiredArgsConstructor`、`@Slf4j`。
- **不得**：实体类使用 `@Data`（破坏相等性与懒加载）；`@SneakyThrows`；在 API 契约类上用会生成无参构造以外行为的注解。

### 5.7 依赖注入与校验

- **必须**构造器注入 + `final` 字段；**不得**字段注入 `@Autowired`。
- 入参校验用 Jakarta Validation，注解写在 DTO；`message` **必须**是 i18n key，**不得**硬编码中文。
- 分页参数 `Pageable` **不得**穿透到 API 层，须转换为自有分页 DTO。

### 5.8 时间与金额

- 时间统一 `Instant`（存储与传输）与 `LocalDate`（纯日期）；**不得**用 `long` 时间戳裸传。
- 金额统一 `BigDecimal` + `ISO 4217` 币种；**不得**用 `double`/`float`。

## 6. TypeScript / Vue 编码规范

### 6.1 类型

- `tsconfig` **必须**开启：`strict`、`noUncheckedIndexedAccess`、`exactOptionalPropertyTypes`、`noImplicitOverride`。
- **不得**使用 `any`；不确定用 `unknown` 并收窄。
- API 类型**必须**由 OpenAPI 生成（`packages/shared`），**不得**在页面里手写重复接口类型。

### 6.2 组件

- 统一 `<script setup lang="ts">` + `<template>` + `<style scoped>`。
- 组件文件 `PascalCase.vue`；组合式函数 `useXxx.ts`。
- **不得**在组件内直接调用 axios；统一走 `api/` 层。
- Props **必须**显式类型与默认值；事件 **必须**声明类型。

### 6.3 状态与请求

- Pinia setup store；**不得**在 store 里直接发请求（由 API 层调用后写入）。
- 请求层统一处理 Problem Details：按状态码分支、`errors[].pointer` 映射表单。
- **必须**处理加载态、空态、错误态三态，禁止只写成功路径。

### 6.4 i18n 与样式

- 文案**必须**走 `$t('key')`；**不得**硬编码中文（ESLint 规则拦截）。
- 颜色/间距/圆角**必须**用设计令牌（CSS 变量）；**不得**散落魔法值。
- 设计令牌层（--vane-*）映射到 Element Plus 变量（--el-*）；业务样式只用令牌，不直接引用组件库变量。
- **不得**使用内联 `style`（动态计算值除外）。

### 6.5 无障碍

- 语义标签优先；表单控件**必须**有关联 `<label>`；图标按钮**必须**有 `aria-label`。
- 目标 **WCAG 2.2 AA**；键盘可完整操作。

## 7. 数据库规范

### 7.1 命名

| 对象 | 规则 | 示例 |
|---|---|---|
| 表 | `<域>_<实体>`，小写下划线，**单数** | `sys_user`、`iam_role`、`sys_dict_item` |
| 列 | 小写下划线 | `created_at`、`is_enabled` |
| 主键 | 一律 `id` | `id` |
| 外键列 | `<实体>_id` | `role_id` |
| 时间列 | 后缀 `_at`，类型 `timestamptz` | `deleted_at` |
| 布尔列 | 前缀 `is_` / `has_` | `is_locked` |
| 索引 | `idx_<表>_<列>` | `idx_sys_user_email` |
| 唯一索引 | `uk_<表>_<列>` | `uk_sys_user_username` |
| 外键约束 | `fk_<表>_<目标表>` | `fk_iam_user_role_role` |

**审计列实现约定**：`created_by / updated_by` 由 Spring Data JPA Auditing 自动填充（`AuditorAware` 取当前登录用户），无认证上下文（启动引导、定时任务）写 `NULL` 表示「系统」；`created_at / updated_at` 由实体显式赋值。经 `JdbcTemplate` 直写的关联表（`iam_user_role` / `iam_role_permission` / `iam_role_dept`）、字典表与系统参数也由 application 层显式传入操作者，写 `created_by / updated_by`。

### 7.2 强制规则

1. **主键**：`uuid`，默认值 `uuidv7()`（PG 18 内置），应用层不自行生成。
2. **审计列**：每张业务实体表必须有 `created_at`、`created_by`、`updated_at`、`updated_by`，由 Spring Data Auditing 填充；字典与关联表至少包含 `created_at`。
3. **乐观锁**：可并发编辑的表必须有 `version bigint not null default 0`。
4. **逻辑删除**：用 `deleted_at timestamptz`；唯一约束**必须**写成部分唯一索引 `WHERE deleted_at IS NULL`，软删后同名唯一值可再次创建。
5. **时间**：一律 `timestamptz`，存 UTC；**不得**用 `timestamp`（无时区）或字符串存时间。
6. **金额**：`numeric(19,4)` + 币种列；**不得**用 `float`/`double`。
7. **枚举**：用 `text` + `CHECK` 约束，**不得**用 PostgreSQL `enum` 类型（演进成本高）。
8. **JSON**：`jsonb` 仅用于非检索用途；**不得**把需要过滤/排序的关键字段塞进 JSON。
9. **外键**：**必须**建真实外键约束（不靠应用层保证），并为其建索引。
10. **字符集**：库与连接统一 UTF-8；排序规则优先 `PG_UNICODE_FAST` 或 ICU。
11. **迁移**：只用 Flyway `V__` 版本化脚本；**不得**使用 `ddl-auto=update`；`R__` 仅用于视图/函数等可重复对象。
12. **认证**：只允许 `scram-sha-256`；**不得**用 `md5`（PG 18 已弃用）。

### 7.3 索引与性能

- 所有外键列、高频查询条件列**必须**有索引。
- 复合索引**必须**按「等值列在前、范围列在后」组织。
- 单表索引数超过 6 个需在 PR 中说明理由。
- 慢查询阈值 200ms，超阈值需给出执行计划说明。

## 8. 接口规范（摘要，详见分册 03）

- **响应模型**：资源式表示 + 真实 HTTP 状态码；错误一律 RFC 9457 `application/problem+json`（见 03 文档）。
- **URL**：`/api/v1/<资源复数>`；kebab-case；嵌套深度 ≤ 2；动作表达为子资源（`POST /orders/{id}/cancel`）。
- **查询**：过滤 `filter[field]=value`；排序 `sort=-createdAt`；分页 `page[size]` + `page[after]`（游标），管理端表格可用 `page[number]`。
- **写操作**：条件更新用 `ETag` + `If-Match`；创建用 `201 + Location`；`PATCH` 用 RFC 7396 `application/merge-patch+json`。
- **契约**：OpenAPI 3.2.1 由代码生成，进 CI 做 breaking-change 校验。

## 9. 国际化规范（摘要，详见分册 04）

- 语言标签 BCP 47；默认 `zh-CN`，同时提供 `en`。
- 后端 `MessageSource` + ICU MessageFormat；前端 `vue-i18n`。
- 文案 key 用语义命名 `module.section.item`，**不得**用中文原文当 key。
- 校验消息、错误码文案、邮件/短信模板、字典项**必须**双语齐备，缺失构建失败。
- 时间/数字/货币一律走 `Intl` 与本地化格式，**不得**手写 `yyyy-MM-dd`。

## 10. 安全基线（摘要，详见分册 06）

- 目标 **OWASP ASVS 5.0 L2**。
- 密码存储 **Argon2id**（首选）或 bcrypt cost ≥ 12；**不得**自研哈希。
- 密码策略：最小长度默认 **6**（可配置；面向等保或 ASVS L2 的场景应配置为 ≥ 12）；不强制复杂度组合；校验弱密码表；不强制定期更换；重置令牌一次性、30 分钟有效。
- 登录锁定：同一账号连续 5 次失败锁定 15 分钟，按**账号 + IP** 双维度计数。
- 认证令牌：access **15 分钟**、客户端只存内存、走 `Authorization: Bearer`；refresh **7 天**、走 `__Host-REFRESH`（`Secure` + `HttpOnly` + `SameSite=Strict` + `Path=/`）。
- refresh **必须**一次性轮换并做复用检测；复用即撤销整个令牌族。
- 服务端令牌状态：access 以哈希存 Valkey（TTL 15 分钟，可即时撤销）；refresh 存哈希与族状态（TTL 7 天）。**不得**存明文令牌。
- 多因素：TOTP（RFC 6238），管理员可选开启；密钥 AES-256-GCM 加密存储（主密钥来自环境变量或 KMS，带版本号）、防重放、时钟容差 ±1 窗口、恢复码一次性；绑定需密码二次确认。
- `login` / `refresh` / `logout` **必须**校验 `Origin`；Bearer 模式下其余接口不需要 CSRF 令牌。
- 响应头**必须**含 HSTS、CSP、`X-Content-Type-Options: nosniff`、`Referrer-Policy`、`Permissions-Policy`。
- 上传**必须**校验真实类型（魔数）、限制大小、SVG 净化、上传目录不可执行。
- 密钥**必须**走环境变量/密钥管理，**不得**入库或进前端产物。
- 详细规则见 [03 §14](03-HTTP语义与错误模型规范.md)。
