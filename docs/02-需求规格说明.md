## 1. 角色

| 角色 | 说明 | 数据范围 |
|---|---|---|
| 超级管理员 | 平台级，含密钥与系统参数 | 全部 |
| 管理员 | 业务管理，不含密钥 | 按授权组织 |
| 运营 / 内容编辑 | 内容与公告维护 | 按授权 |
| 审计员 | 只读日志与审计，不可改业务 | 全部（只读） |
| 普通用户 | 前台门户 | 仅本人 |
| 访客 | 未登录用户 | 仅公开内容 |

## 2. 权限模型

**功能权限**：RBAC。权限点（按钮级）↔ 角色 ↔ 用户；菜单可见性由权限点派生。

**数据权限**：五种范围，绑定在角色上。

| 范围 | 含义 |
|---|---|
| 全部 | 不限组织 |
| 本组织及以下 | 当前用户所属组织及其下级 |
| 本组织 | 仅当前组织 |
| 仅本人 | 仅本人创建或负责的数据 |
| 自定义 | 指定若干组织 |

**实现约束**：

- 数据范围**必须**在查询构建阶段统一注入，业务代码不手工拼条件。
- 每张受控表登记归属列（如 `dept_id`）；未登记的表不参与隔离。
- 全局查询场景（登录、字典、定时任务）使用显式豁免注解，豁免项白名单管理并记审计。
- 越权测试覆盖每张受控表的列表、详情、导出三类接口。

## 3. 编号与优先级

- 功能编号：后台 `ADM-xx`，前台 `PTL-xx`；新增功能递增编号，不复用已废弃编号。
- 优先级：**P0** 必须实现（模板可用性的底线）、**P1** 应当实现、**P2** 可延后。
- 非功能需求（性能、安全、可访问性、兼容性）见 [01 附录 A 标准基线](01-技术栈与规范基线.md)。
